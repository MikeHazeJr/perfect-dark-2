### Critical Issues

- **PD-01 (CARRYOVER) — `struct packedpad` bitfield of signed `s32` fields over a persisted pad-file word**
  - Severity: Critical · Confidence: Confirmed (re-verified 2026-10-30) · Area: Design Fit / Code Quality
  - Location: `src/include/types.h:323-333` — LE branch declares `s32 liftnum:4; s32 room:10; s32 flags:18;`. Consumers: `src/game/setuppads.c:230, 234, 248, 250` read `packedpad->room` through the bitfield; `:257` works around via raw mask (`(*(u32 *) packedpad >> 14) & PADFLAG_HASBBOXDATA`). Producer: `port/src/preprocess/filepads.c:17-29, 57-61` stores a semantic u32 directly.
  - Lineage: Inherited-from-n64decomp · Pillar Impact: Scaling Ceiling (indirect) · Defect Class: Layout
  - **Nuance refinement (2026-10-30):** Re-reading the LE bit layout, the field ordering is actually self-consistent with the producer under GCC/Clang LE semantics (`liftnum` → bits 0-3, `room` → 4-13, `flags` → 14-31; matches the producer's bit layout). The **active defect** is not the field order but the **signed storage type**: `s32 room:10` sign-extends on read, so any stage with a room number whose bit 9 is set (room ≥ 512) returns negative from `packedpad->room`. Likewise `s32 flags:18` sign-extends bit 17 so flag reads above `1<<17` go negative. The check at `setuppads.c:234` (`if (packedpad->room < 0)`) actively conflates sign extension with a sentinel, meaning any legitimate high-numbered room is silently reassigned via the fallback at :248-250. The BE branch (`s32 liftnum:4; s32 flags:18; s32 room:10;`) is independently wrong but inert on PC-only.
  - Why It Matters: PD2 is PC-only (LE); stages with ≥512 rooms are not currently in content but the fragile idiom is one Forge expansion away from biting. The absence of `_Static_assert(sizeof(struct packedpad) == 4)` and a round-trip test means any future bitfield edit silently redefines the on-disk word.
  - Risk If Not Fixed: Latent on current content; one stage with a high room number will corrupt pad routing.
  - Recommendation: Change the storage type to `u32` (not `s32`); add `_Static_assert(sizeof(struct packedpad) == 4)`; add a round-trip test that encodes {flags, room, liftnum} tuples (including values at bit boundaries like room=512) and reads them back. Prefer the raw mask/shift idiom at `:257` as the single consumer pattern. · Cross-System: Yes · Blocks Intended Outcome: Partially.
