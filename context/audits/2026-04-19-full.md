## Critical Findings (6)

### MASTER-C1: `netbufReadStr` non-NUL-terminated string API — 60+ OOB read hazard sites
- **Location:** `port/src/net/netbuf.c:120-129`
- **Lineage:** Inherited from port-net
- **Impact:** Every string-carrying CLC/SVC message is exploitable. Heap OOB reads, crash-on-join DoS, information disclosure via re-broadcast, killfeed/chat spoofing.
- **Fix:** One-function change in `netbufReadStr` to enforce NUL termination. Protects all 60+ downstream sites at once. ~4 hours.
- **Both Catalog+Netplay and Server+Security independently identified this as #1 priority.**

### MASTER-C2: Dedicated server has no authentication, admin API, or persistent ban
- **Location:** `port/src/server_main.c`, `port/src/server_bridge.c`
- **Source:** Server+Security (SEC-2)
- **Impact:** Any peer connects with any name. No kick persistence. No headless admin. Blocks public hosting entirely.
- **Fix:** Admin token + RCON channel + persistent `bans.ini`. ~3-5 days.

### MASTER-C3: Preserved-player slot hijack via name spoof (→ MASTER-H1 escalated)
- **Location:** `port/src/net/net.c:1169-1181`, `port/src/net/netmsg.c:471`
- **Source:** Catalog+Netplay (H-1) + Server+Security (SEC-3)
- **Impact:** Any peer who knows a player's name can steal their score, team, and slot on reconnect. Zero-skill griefing vector.
- **Fix:** Server-issued 128-bit cookie in CLC_AUTH/SVC_AUTH. Protocol bump to v38. ~1 day.

### MASTER-C4: CLC_CHAT rate limiter state not reset per client — wrap-around allows unlimited rate
- **Location:** `port/src/net/netmsg.c:558-572`
- **Source:** Server+Security (SEC-4)
- **Impact:** Client slot handoff inherits stale rate state; low-confidence burst amplification.
- **Fix:** Zero `s_ChatRate[i]` in `netClientReset`. One-line fix.

### MASTER-C5: "Game-agnostic dedicated server" pillar unmet — PD2 types throughout server core
- **Location:** `port/src/server_stubs.c` (71 hardcoded arena entries), `server_bridge.c`, `server_main.c`
- **Source:** Server+Security (DS-1)
- **Impact:** No per-game plugin boundary. Pillar promise unfulfillable without major refactor.
- **Fix:** Either design the plugin boundary (4-8 weeks) or formally retire the pillar. Not a release blocker for PD2 v0.1.0 unless pillar is must-have.

### MASTER-C6: Charpreview FBO permanently black on standalone ImGui screens
- **Location:** `port/fast3d/pdgui_charpreview.c:485-597`
- **Source:** Rendering (REND-C1)
- **Impact:** Every new-generation ImGui menu screen shows placeholder silhouette instead of 3D model preview. Most visible UX failure in the menu system.
- **Fix:** Add `pdguiCharPreviewRenderDirect()` driven from pre-ImGui hook. ~2-4 days.

## Cross-Cutting Concerns (No Single Scope Could See)

### X-1: String-on-wire discipline is unenforced project-wide
Both Catalog+Netplay and Server+Security independently flagged `netbufReadStr` as the #1 finding. The API shape (returning a raw pointer into the packet buffer without NUL guarantee) is the single systemic vulnerability class across the entire networking layer. A `netbufReadStrTo(dst, dstlen)` safe-copy variant would retire the entire class.

### X-2: Trust model asymmetry client ↔ server
Clients trust server-sourced strings unconditionally (kill feed, stage start, catalog info, distribution payloads, room settings). Servers validate client strings somewhat better but are still vulnerable via MASTER-C1. The dedicated-server security posture (no auth, no admin, no persistent ban) compounds this — public hosting is unviable without SEC-2 + SEC-3 fixes.

### X-3: Scaling ceilings cluster across all four scopes
- **Wire protocol:** u64 active-slot mask (64 slots), `CATALOG_COLLECT_MAX=256`, `NET_MAX_CLIENTS=32`
- **Broadcast:** O(bots × clients) per tick, O(clients²) player-move mesh
- **UI:** `MAX_PLAYERS=8` mirrored in 5+ C++ render files, team color arrays hardcoded to 8
- **Rendering:** VBO 256 triangles, texture cache 1024 entries, matrix stack 11
The stated pillar "host-bound scaling" is contradicted at every layer. Interest management (PVS culling) in the network layer would have the highest single impact.

### X-4: Registration-path asymmetry (mod vs native)
Locally-scanned mods go through typed registrars. Wire-delivered mods go through `assetCatalogRegister(ASSET_NONE)`. This is the same class of asymmetry across Catalog+Netplay (H-2) and the mod-parity audit — "if you stripped the labels, you couldn't tell" is violated at the ingestion boundary even though it holds at the resolve boundary.

### X-5: Legacy GBI coupling blocks modern UI
The rendering audit's MASTER-C6 (charpreview FBO unreachable from standalone screens) is architecturally related to the menu audit's observation that ImGui menus have fully replaced legacy rendering. The legacy `menuRenderDialog` GBI phase is now the only render-dispatch path for model previews, but the UI layer has moved past it. This coupling will recur for every new feature that needs in-menu 3D rendering (Forge preview, weapon inspect, prop placement preview).

### X-6: Data-layout drift hazard spans rendering and networking
- `struct gset` serialized as raw bytes on the wire (Server+Security LAYOUT-1)
- `struct mpchrconfig` byte-offset comments stale by ~128 bytes (Menus F-StaleStructComments)
- UV arithmetic `s16 × u16` overflow (Rendering REND-H1)
- `lobbyGetPlayerInfo` hand-packed by byte offset (Server+Security CQ-5)
All four are the same defect class: in-memory layout treated as stable interface without verification. `static_assert(offsetof(...))` at load-bearing sites would catch future drift.
