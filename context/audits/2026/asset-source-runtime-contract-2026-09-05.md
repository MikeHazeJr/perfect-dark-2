## Larger incomplete contracts

### Graph execution

`weapon_graph_runtime.c` compiles edges, subgraphs, and shared context, but its
held adapter projects exported/mode nodes into two function records and its
projectile/entity adapters scan node arrays into scalar records. This does not
prove authored edges, gates, event flow, or shared state govern gameplay.
Named native C modules are permitted by D-004; silently ignored graph semantics
are not. D-006 records the architectural choice between a versioned executable
graph layer using those modules and a strictly limited module-composition
authoring contract. Narrow source-authority repairs do not resolve D-006.

The same audit identifies base-weapon early returns in `propobj.c` before
projectile/entity graph lookup and custom-slot-only transition gates in
`bondgun.c`/`propobj.c`. Removing these requires a parity audit of the native
module dispatch to avoid double execution. Source-reference validation alone
does not repair these production bypasses.

### Standard glTF visual semantics

The current `parseGltfMeshFromJson` imports positions, private room tags,
triangle indices, and base color factors. It does not preserve standard scene
node transforms, UVs, normals, vertex colors, skins, or texture/material
bindings. Accepting a `.gltf` or `.glb` suffix is therefore not full DCC import
support. Buffer-source support alone cannot close this gap. The complete
contract requires active-scene traversal, correct transform/normal handling,
material and texture dependency mapping, and deliberate skin/animation support
with edited-source runtime and visual proof.

The standard reference is the [Khronos glTF 2.0 specification](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html),
especially URIs, buffer storage, node transformations, mesh attributes, and
materials. Private generated runtime products remain rebuildable cache.

### Other authoring limitations

The animation special-parts path rebuilds all native parts from captured source
data, so accepting edited glTF channels does not establish round-trip control
for those clips (`modasset_compiler.c:gltfBuildAnimationClipPayload`).
`romextract_pdlang.c` emits the selected English bank with regional handling
explicitly deferred; all regional language content is not established by the
current extraction count. Legacy game text still uses PGM/metrics through
`fontCatalogBuildFace`, while vector TTF/OTF handling serves the ImGui font path.
These are distinct consumer/semantic gaps, separate from the three current
repair tasks and from unexecuted all-family validation coverage.

### Completeness evidence

Historical all-family archive conformance and package round-trip are useful
regression evidence, but they do not prove every original semantic is emitted
or that an edited source changes its production consumer. The extraction and
runtime umbrellas remain partial until the current family/field matrix and
edited-source Campaign/Combat Simulator gates pass. A parser rejection test is
not gameplay or visual proof.
