# Front-end control audit, November 19, 2026

The audit traced the main menu, Agent Select and Create, local and connected Rooms, Social, the match ready gate, and The Grid. The source baselines are canonical `dev` at `da5163e44`, the local PR 13 ref at `ddac61d64`, and the shipped Grid v0.1.105 tag at `8556dc8de`. The findings below describe reachable source paths. Prior client evidence is identified by build or receipt.

## P1 findings

### Online match preparation can leave the player without consent or advertised Cancel

Acceptance of a match manifest sets the guest to `CLSTATE_PREPARING`. The lobby renderer only keeps the Room and draws the download-consent overlay in exact `CLSTATE_LOBBY`. Its alternate branch releases both possible lobby owners. For missing content that requires consent, the protocol then waits for the player's decision while Download, This Session and Skip are absent. This applies to canonical `dev` and the reviewed PR 13 ref. [Manifest receive](../../../port/src/net/netmsg.c#L13064) · [Lobby-state predicate](../../../port/fast3d/pdgui_bridge.c#L358) · [Lobby render and release](../../../port/fast3d/pdgui_lobby.cpp#L521) · [Manifest waits for consent](../../../port/src/net/netmanifest.c#L2591)

The guest countdown draws independently, owns no menu context, and only polls mapped Back. Once the lobby is the last owner to release, the normal advertised Escape/B bindings leave with it. A gameplay binding that happens to resolve to the cancel action can still reach the handler. The countdown offers no clickable Cancel. The listen host has a local cancel handler, but the countdown UI state is populated by a message sent to remote peers, so the in-process host has no normal countdown surface. Preserve an explicit preparation UI owner through consent and countdown, keep the cancel operation visible to each authorized role, and hand off to gameplay only when the stage starts. [Countdown input](../../../port/fast3d/pdgui_countdown.cpp#L120) · [Menu context release](../../../port/src/inputctx.c#L811) · [Countdown publication](../../../port/src/net/netmsg.c#L11063) · [Peer send](../../../port/src/net/net.c#L4617)

### New Agent loses controller navigation on canonical dev

Agent Select releases its context before pushing Create. The legacy push allocates the destination with a null context and the Create renderer never attaches `g_CtxImGuiMenu`. The controller navigation bridge requires an active non-gameplay context. A player using only a controller can reach the visible form and lose mapped navigation and the route to controller name entry. Two logs from Mike's separate PC witnessed the same missing ownership in Grid v0.1.103 (N-1005). Grid v0.1.104 added the context acquisition and release at `04ab278e0`, inherited by v0.1.105. The fix is available for the canonical lane and has focused build/test evidence on Grid (N-1004). [Agent handoff](../../../port/fast3d/pdgui_menu_agentselect.cpp#L944) · [Legacy push](../../../src/game/menu.c#L1556) · [Create renderer](../../../port/fast3d/pdgui_menu_agentcreate.cpp#L424) · [Navigation admission](../../../port/fast3d/pdgui_backend.cpp#L576)

### The Grid controller can enter the editor without reaching its ordinary controls

In shipped v0.1.105, the Forge editor keeps a hybrid camera/sidebar context. The physical D-pad and A feed Forge sidebar actions, and the sidebar only opens certain dedicated tools or scrolls to sections. Ordinary fields and buttons such as Level Name and Save As Level still need normal ImGui navigation. Save As with a mod dependency can also open a confirmation with only on-screen Save and Cancel and no controller ownership or Back handler. Mouse works as a recovery path. Native Placement and Level Tools already hand off to normal menu input. Use that ownership boundary for the interactive editor sections and save confirmation, with a return to the same section or camera. At `8556dc8de` see `pdgui_forge_editor.cpp` lines 1430–1463, 1708–1741, 2803, 3100, 3959–3961 and 4317–4333. The analogous Forge context exists in canonical `dev`. [Forge context](../../../port/src/inputctx.c#L937) · [Controller bridge](../../../port/fast3d/pdgui_backend.cpp#L601)

### Controller navigation can strand the player even with usable hardware attached

Front-end navigation reads actions from slot 0. Removal clears the departing slot and leaves an already attached second controller in slot 1. The second controller's events continue to route to its assigned slot, so it cannot take over the visible UI. `Input.FirstGamepadNum` can produce the same slot gap at startup. Keyboard/mouse or reconnecting a pad into the vacant slot can recover. A front-end controller owner can fall back to an eligible connected pad while preserving gameplay slot assignments. [Removal](../../../port/src/input.c#L371) · [Slot preference](../../../port/src/input.c#L1604) · [Event dispatch](../../../port/src/actionmap.cpp#L1363) · [Slot-0 navigation](../../../port/fast3d/pdgui_backend.cpp#L601)

Settings also permits clearing the last controller binding for Accept, Back or a direction and immediately saves the edit. The sole default controller Accept is A. The device's ordinary action to select Reset Defaults can disappear with it. Validate a profile's recovery path before applying it or provide a controller recovery gesture that survives changes to the profile. [Binding clear](../../../port/fast3d/pdgui_menu_mainmenu.cpp#L2363) · [Default bindings](../../../port/src/actionmap.cpp#L3387) · [Reset Defaults](../../../port/fast3d/pdgui_menu_mainmenu.cpp#L3854)

## P2 findings

- **Back goes through Social to the underlying screen.** The Room, connected lobby and Agent Select render before Social and can read the same mapped Back. With the modeless Friends sidebar or Social shell open, the underlying Room can open Leave, the connected lobby can open Disconnect, or Agent Select can pop before the intended receiver handles Back. Room tab navigation has the same ownership gap. The main menu already defers its Back and Social commands to higher Social surfaces. The invariant belongs at the input owner boundary so each gesture changes exactly the active screen. [Render order](../../../port/fast3d/pdgui_backend.cpp#L1000) · [Room Back](../../../port/fast3d/pdgui_menu_room.cpp#L3924) · [Lobby Back](../../../port/fast3d/pdgui_menu_lobby.cpp#L488) · [Agent Select Back](../../../port/fast3d/pdgui_menu_agentselect.cpp#L410) · [Main menu guard](../../../port/fast3d/pdgui_menu_mainmenu.cpp#L6223)
- **Agent title-bar X misses the actual close handler.** Agent Select, Create and the Copy/Delete modal draw a title X but only read mapped Back in their close branches. The title posts a separate close flag and synthetic ImGui Escape, which does not raise the action-map edge. The picker lacks another visible left-click Back. Create still has a clickable Cancel. Route title X, visible Cancel and mapped Back through the same topmost close transaction. [Title close event](../../../port/fast3d/pdgui_style.cpp#L651) · [Picker](../../../port/fast3d/pdgui_menu_agentselect.cpp#L368) · [Copy/Delete](../../../port/fast3d/pdgui_menu_agentselect.cpp#L738) · [Create Back](../../../port/fast3d/pdgui_menu_agentcreate.cpp#L740)
- **Canonical first-run Agent timing depends on frame rate.** The runtime still admits the picker during an active first-run camera once the render count passes 300, and the picker minimum also counts rendered frames. The Grid fix at `04ab278e0` uses elapsed level ticks and retains a six-second watchdog. N-1010 proved the camera-to-picker sequence on a corrected Grid candidate. [First-run gate](../../../src/game/menutick.c#L67) · [Picker delay](../../../src/game/menutick.c#L519)

## Acceptance rule and next checks

Every visible interactive screen needs a designated input owner and a reachable exit or recovery action on the device currently in use. A transition should preserve the previous owner until the next screen can accept input, then restore an actionable focus target on return. For each handoff, verify that one fresh gesture affects exactly one surface, held inputs do not activate the destination, and the next fresh gesture works after Alt-Tab, capture cancellation, or controller removal. Record the visible outcome, authoritative context and absence of an underlying action in the same run.

Start with online manifest consent and countdown Cancel, fresh Agent Create, controller removal with a second pad already attached, then Grid editor Save As and Play Draft return. Also run Main Menu > Settings > Back, Room > Social > Back, and results > Room with keyboard, mouse and physical controller. Use the current menu verification gate V-004 and the existing networking and Grid items for branch-specific follow-through.
