### Critical Issues

- **PD-01 (CARRYOVER) — `struct packedpad` signed-bitfield sign-extension on persisted pad word**
  - Severity: Critical · Confidence: Confirmed (re-verified 2026-11-06 via `git show HEAD:src/include/types.h`) · Area: Design Fit / Code Quality
  - Location: `src/include/types.h:323-333` — LE branch declares `s32 liftnum:4; s32 room:10; s32 flags:18;`. Consumers: `src/game/setuppads.c:230, 234, 248, 250`, with raw mask workaround at `:257`. Producer: `port/src/preprocess/filepads.c:17-29, 57-61` stores a semantic u32 directly.
  - Lineage: Inherited-from-n64decomp · Pillar Impact: Scaling Ceiling (indirect) · Defect Class: Layout
  - The active defect is the signed storage type: `s32 room:10` sign-extends on read, so any room ≥ 512 reads negative; `s32 flags:18` sign-extends bit 17. `setuppads.c:234` conflates sign extension with a sentinel and falls through to the fallback assignment at `:248-250`. No `_Static_assert(sizeof(struct packedpad) == 4)` exists.
  - Why It Matters: PD2 is PC-only (LE); current content does not yet contain stages with room ≥ 512, but Forge level authoring is a specified near-term target and will exceed 512 rooms in ambitious maps. The fragile idiom silently mis-routes on crossing that threshold.
  - Recommendation: Change storage to `u32`; add `_Static_assert(sizeof(struct packedpad) == 4)`; add a round-trip test at bit boundaries (room=512, flags=1<<17). Prefer the raw mask/shift idiom at `:257` as the single consumer pattern.
  - Cross-System: Yes · Blocks Intended Outcome: Partially.

- **PD-01A (CARRYOVER) — Agent-profile persistence uses locale-sensitive `fprintf("%.9g", …)` + `strtod` without locale pinning**
  - Severity: Critical · Confidence: Confirmed (re-verified 2026-11-06) · Area: Design Fit / Code Quality
  - Writer: `port/src/agent_profile_codec.c:1012-1028` (`scanline_alpha`, `master_volume`, `music_volume`, `gameplay_volume`, `ui_volume`, `screen_shake_intensity`). Reader: `agent_profile_codec.c:275-288, 1234-1238`, plus a second `strtod` site at `:1074` (PD-M06). **Grep for `setlocale|uselocale|newlocale` in `port/src/*.c` and `port/src/*.cpp` returns zero hits on 2026-11-06.**
  - Lineage: Authored-in-PD2 · Pillar Impact: Modding Pipeline (determinism-adjacent) + user data integrity · Defect Class: Determinism / Layout (persisted)
  - On any Windows install with a non-C `LC_NUMERIC` (de_DE, fr_FR, nl_NL, ru_RU, es_ES, it_IT, pt_BR, …), `fprintf` writes `0,5` and `strtod("0,5", &end)` returns 0.0 with `*end=','` which the reader rejects. Every non-English user sees audio/visual preferences silently reset to defaults every launch.
  - Risk If Not Fixed: First-impression defect for European modding community; and silently poisons `.pdmod` SHA-256 digests computed on non-C-locale authoring machines (breaking distribution integrity).
  - Recommendation: `uselocale(newlocale(LC_NUMERIC_MASK, "C", (locale_t)0))` scoped at `main()` entry OR around every writer/reader in `port/src/`. Add `LC_ALL=de_DE.UTF-8 ./pd-tests` CI job.
  - Cross-System: Yes.

- **PD-02 (CARRYOVER) — PDCA archive format has no version word**
  - Severity: Critical · Confidence: Confirmed (re-verified 2026-11-06 at `port/src/modpack.c:36, 220-275`) · Area: Design Fit
  - Location: `port/src/modpack.c:36 #define PDCA_MAGIC 0x41434450u`; builder at `:220` writes `magic(4) + file_count(2)` only; extractor at `:263-275` consumes that same layout. The outer `PDPK_VERSION` pack format does carry a version word; PDCA, the inner archive, does not.
  - Lineage: Authored-in-PD2 · Pillar Impact: Modding Pipeline · Defect Class: Layout
  - Any future header change (per-member hash, flags byte, padding word) will silently misinterpret older artifacts. Pre-1.0 is the only cheap moment to fix this.
  - Recommendation: Insert a `u16` version word after the magic now and switch `PDCA_MAGIC` to a fresh constant at the same time to force clear separation between old and new blobs. Gate deserialization on the version. Cross-System: Yes.
