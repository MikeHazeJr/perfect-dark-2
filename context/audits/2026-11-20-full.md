## 2) Design Intent & Gameplay / Multiplayer Fit Review

### Critical Issues

- **CAT-C01 — `.pdpack` extractor has no path-traversal defense**
  - Severity: Critical · Confidence: Confirmed · Area: Security / Design Fit · Defect Class: Trust-Boundary / Supply-Chain · Pillar: Modding Pipeline supply-chain integrity · Lineage: Authored-in-PD2
  - Location: `port/src/modpack.c::extractArchive` lines 264-323; called from `modpackImport:856`. Specifically `:288` `const char *relpath = (const char *)p;` and `:298` `snprintf(outpath, sizeof(outpath), "%s/%s", destdir, relpath);`
  - Intended Outcome: a user-installed `.pdpack` is extracted only under the mods directory the installer selected.
  - Current Behavior (from code evidence): the archive entry's path field is used verbatim as the join suffix. No `..` component check, no absolute-path rejection, no backslash normalization, no reserved-device (CON/NUL/LPT1/…) check. The newer `pdca_extract_transaction.c` uses `assetPathJoinChecked` + `componentIsReservedDevice` and would refuse the same input.
  - Gap / Failure Mode: a hostile `.pdpack` whose central directory names an entry `../../AppData/Roaming/Microsoft/Windows/Start Menu/Programs/Startup/pwn.cmd` writes a startup entry the next time the user reboots. Shared on Discord, one click.
  - Why It Matters: the pillar aims to ship a modding platform to a community that routinely exchanges user-authored content. One extractor without traversal defense invalidates the whole chain.
  - Risk If Not Fixed: arbitrary file write anywhere the game process can write → RCE-adjacent via Startup-folder / scheduled-task / autorun persistence. A single malicious seeder in a Grid room owns every joining client.
  - Recommendation: route `modpack.c::extractArchive` through `pdcaExtractArchiveTransactional`, or inline the same `assetPathJoinChecked` + component reserved-device check. Reject backslash and drive-letter prefixes explicitly on Windows.
  - Cross-System Changes Required: No (localized to `modpack.c`) · Blocks Intended Outcome: Yes (release-blocker).

- **CAT-C02 — `.pdpack` build is non-deterministic (three sources)**
  - Severity: Critical · Confidence: Confirmed · Area: Design Fit · Defect Class: Determinism · Pillar: Modding Pipeline · Lineage: Authored-in-PD2
  - Location: `port/src/modpack.c::modpackExport:439-507` and `buildArchiveDir:142-214`
  - Intended Outcome: identical inputs yield byte-identical outputs — the modding pipeline's own stated invariant.
  - Current Behavior: three non-deterministic sources: (1) `:471-473` writes `created=%Y-%m-%d` from `time(NULL)` + `localtime`; (2) `:149` raw `readdir()` with no sort (NTFS MFT order, ext4 hash order, differs across tooling); (3) component archive content inherits readdir order.
  - Gap: Any contract that assumes byte-identical rebuilds (Catalog SHA, future signing, reproducible-builds posture) is silently broken.
  - Why It Matters: Future mod signing / Catalog-hash-based cache keys / Grid package digests all assume this invariant. Breaking the invariant retroactively invalidates every signed artifact.
  - Risk: Silent divergence between "I built this mod yesterday" and "I built it today"; signing infrastructure never ships; Grid trust chain cannot be upgraded.
  - Recommendation: (a) replace `readdir()` loop with collect-then-`qsort` by name; (b) remove `created=` field entirely or pin to a caller-supplied `$SOURCE_DATE_EPOCH`-shaped value.
  - Cross-System: No · Blocks Intended Outcome: Yes.

- **CQ-02 (CARRYOVER, anchor lines corrected) — Pointer-width truncation in weapon_nested_runtime_harness**
  - Severity: Critical · Confidence: Confirmed · Area: Code Quality · Defect Class: Layout (pointer-width) · Lineage: port-net
  - Current anchors (five sites, corrected from 2026-11-06): `port/src/weapon_nested_runtime_harness.c:1117, 1133, 1513, 1541, 1603`. Lines `:1253-1255` previously bundled with CQ-02 are GBI opcode-format bit extracts and are correct — **remove from CQ-02's bill**.
  - Shape: `gdl[i].words.w1 == (uintptr_t)pixels` compares a 32-bit `u32 w1` against a 64-bit `uintptr_t`. On 64-bit MinGW, any `pixels` outside the low 4 GiB mismatches silently.
  - Recommendation: store the pointer as two words (`w0`+`w1`) or as a 64-bit side-channel index into a texture-pointer table; never try to round-trip a 64-bit pointer through one 32-bit GBI word.

- **CQ-03 (CARRYOVER + MASSIVELY WIDENED) — Unbounded `.pdmod` member allocation, now 62 call sites across 30 files**
  - Severity: Critical · Confidence: Confirmed · Area: Security / Code Quality · Defect Class: Trust-Boundary / Supply-Chain · Pillar: Modding Pipeline + Grid Trust
  - Count progression: 10 (2026-10-16) → 12 (2026-11-06/-11-13) → **62 at HEAD** (one of those is the definition site at `port/src/modarchive.c:833`, so **61 consumer call sites**).
  - Sink: `modArchiveExtractMemAlloc(archive, size, path, &out_size)` at `modarchive.c:867` → `u8 *out = (u8 *)malloc(e->size_uncompressed);` where `size_uncompressed` is a `u32` read straight from the archive header. No per-call size cap, no ratio ceiling.
  - Full file:line enumeration is in §Top Data-Layout Integrity Breaches, below. New subsystems contributing since 2026-11-13: Grid match cache / match package I/O / match runtime / edit room (6 sites), Forge level I/O + room builder (3), mod_author (1), body/head source (4), texture-source upgrade (1), native_asset_consumer_trace (1), pdeffect_source_parser (1), pdgui_menu_moddinghub (1), model_source_path / modvfs (2).
  - Partial: `grid_match_cache.c:170` is the one site under a `grid_archive_budget_t` wrapper — a correct implementation local to Grid validator recursion, but every other site is unbounded.
  - Risk: a 1 KB `.pdmod` whose zip entry declares `size_uncompressed = 0xFFFFFFFF` requests 4 GB on every extract. Even a `malloc` failure is a DoS when it lands on a Grid match download hot path or during Combat-Simulator lobby entry. Zip-bomb amplification ~1000:1 under raw deflate.
  - Recommendation (unchanged from 2026-11-06, now with wider blast radius): add a shared `modArchiveExtractBudgeted(archive, size, path, size_cap, ratio_cap, out_len)` wrapper and migrate all 61 call sites. Caps per content category: ini/descriptor ≤ 16 MiB, geometry/texture ≤ 256 MiB, nested = caller's remaining budget. **This is the single highest-leverage fix in this audit.** Close PDCA format too (PD-02 extract-transaction) in the same cut.

- **CQ-A01 (CARRYOVER, re-scored to Medium-latent) — GGV `Builder::append` cross-source splicing without entry/exit labels**
  - Still at `port/src/gameplay_graph_values.cpp:462`: `if (n.op==GGV_BRANCH_FALSE || n.op==GGV_JUMP || n.op==GGV_REPEAT_WHILE) n.target += offset;`

- **NET-H01 — `SVC_NPC_SPAWN` applies unchecked wire fields directly to chr state**
  - Severity: High · Confidence: Probable · Area: Security / Design Fit · Defect Class: Trust-Boundary (host → client) · Pillar: Online-mode Boundary · Lineage: Authored-in-PD2 (v64)
  - Location: `port/src/net/netmsg.c:8971-9072` (`netmsgSvcNpcSpawnRead`)
  - Current Behavior: reads `chrnum`/`bodynum`/`headnum` (s16), `team` (u8), `chrflags`/`hidden`/`flags`/`flags2` (u32 each), up to two weapon triples, and `hatmodelnum` directly from wire, then calls `chrSpawnReplicated(bodynum, headnum, …)`, `chr->team = team`, `chr->chrflags = chrflags`, `chr->hidden = hidden`, `chr->flags = flags`, `chr->flags2 = flags2`, `chrGiveWeapon(chr, wmodelnum[i], wweaponnum[i], wobjflags[i])`, `hatCreateForChr(chr, hatmodelnum)`. No bounds against the catalog, no `team < MAX_TEAMS` guard, no flag-whitelist mask, no `wmodelnum` resolution via `catalogGetModelHandle` / `spawnWeaponNumIsResolved`.

Add `_Static_assert(sizeof(wsyncid) / sizeof(wsyncid[0]) == 2)`.

### Medium Priority Findings

- **NET-M01 — `netmsgReconnectProjectileRead` reads 30+ F32s without inf/NaN guards**
  - Location: `port/src/net/netmsg.c:1768-1830`. Fields `speed`, `nextsteppos`, `unk010…unk0f0`, `hominggain`, `homingdamping`, matrices all pass through `netbufReadF32` with no finite-check.
  - Risk: a malicious host injects NaN/Inf that propagates into physics, producing permanent projectile desync (a gentler cousin of crash).
  - Recommendation: add `netbufReadFiniteF32(src)` helper (returns 0.0 on inf/nan) and route projectile/matrix reads through it. Also apply to scenario-state reads where the exhaustive finite-check at `net_scenario_state_wire.c:42-100+` is absent.

## 5) Cross-Cutting Risks & Architecture Concerns

1. **Trust asymmetry between server-ingress and client-ingress.** The host validates every `CLC_*` under `netmsgClc*Read` paths, but the mirror-direction `SVC_*` readers on clients routinely skip the same clamps on the "server is trusted" invariant. In a P2P listen-host model where the host is community-advertised, this invariant is weaker than in a dedicated-server model. **Recommendation:** promote the `gridMatchOfferRead` shape to a documented "wire validator contract" and audit every SVC_* handler against it. Closes NET-H01, NET-H02, NET-H03, NET-M01, NET-M05 in one coordinated pass.

2. **Archive extraction has no shared budget layer.** 61 call sites feed one unbounded sink (`modArchiveExtractMemAlloc`). The one example of correct budget-propagation (`grid_match_cache.c:170` under `grid_archive_budget_t`) is local to Grid validator recursion. **Recommendation:** make the budget wrapper mandatory; retire the raw sink from the public header. One shared PR closes CQ-03 across all 61 sites.

3. **Two archive formats both called "PDCA" diverge.** `modpack.c` (uncompressed `(u16,path,u32,data)`) and `modarchive.c` (ZIP-shape with deflate) share magic, don't share version, and are used in different flows. **Recommendation:** add version word to both; converge on one extractor (ideally the hardened `pdcaExtractArchiveTransactional`).

4. **Save durability.** Non-atomic `fopen(w) → fprintf → fclose` across agent/player/mpsetup. A single crash erases progression. **Recommendation:** temp-file-plus-rename across the board; one 30-line helper, reused at every save callsite.

5. **Locale pinning.** Single-line `setlocale(LC_NUMERIC, "C")` at port init simultaneously closes CQ-01, PD-01A read path, and every future `%g`-shape writer defect. **Do this before anything else in the determinism plan.**

6. **Grid mod-proposal availability.** Every Grid handler should carry a per-peer rate cap mirroring SP-81's shape, so a single hostile room member cannot DoS proposal flow.

7. **NAT Diagnostics debug panel.** The panel exists for a reason; replace octets with connect codes by default, gate raw octets behind a dev build flag. Preserves the debug utility, closes the doxxing-via-screenshot surface.

8. **Theater format trust.** If Theater files ever flow through Grid (currently unclear), the `payload_length` / `index_length` consumer-side bounds become load-bearing. **Recommendation:** add a one-pass validator to `theaterFormatReaderOpen` regardless of future Grid plans.

9. **GGV reversion creates a "shadow spec" lull.** The oracle-tested stock programs are a strong architectural position, but the D-006 "any behavior as nodes" bar is unmet while bondgun.c runs natively. **Recommendation:** when the migration resumes, land it as `(a)` orphan files wired into CMakeLists, `(b)` tests, `(c)` `#ifdef PD_GGV_BONDGUN`-gated migration in that order, each as a "fresh clone builds and tests green" commit.

10. **`union soundnumhack` endian branch** has no persistence audit. If any save/wire/mod ever carries `soundnumhack.packed` as a 16-bit word, portability between the two `PLATFORM_BIG_ENDIAN` branches is not asserted. **Recommendation:** add `_Static_assert(sizeof(union soundnumhack) == 2)` and trace callers.
