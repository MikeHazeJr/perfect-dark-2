Super Audit — PD2 Project State, 2026-05-06
Headline score: 583 / 1000
Code-only baseline from 2026-04-27 was 675. The lower project-wide number reflects that code is strong but stability and online are dragging it down hard. Specifically, the project ships well-architected work that doesn't yet boot reliably, doesn't yet network, and doesn't yet let modders mod in any meaningful sense beyond drop-in replacement.
This is harsh because you asked for it harsh. The work that's been done is substantial and disciplined. The gap between "platform-ready" and where we sit is also substantial.

Rubric — 10 dimensions, 100 points each
1. Architectural integrity — 80 / 100
What's working: catalog universality is a genuinely good design — per-asset files, walker-as-sole-source, BYOR end-to-end, no .pdbase anywhere in the runtime path. Universal input grammar lifted from the Combat Sim binding spec. Pillar-goal naming. "No half-measures" / "migrate-first-then-fix-structurally" are encoded as durable principles and they get applied. Authoring source-of-truth files in Option B uniform across metadata kinds.
What's dragging it: the F13 → Step 5 → BYOR completion saga revealed three structural gaps in sequence, each requiring its own triage to find. The Combat Sim modal-stuck regression that was thought fixed at 24e9b67e is reopening. B-323 and B-324 hit the same code path with different roots. The pattern is "good principles, multiple gap-discovery cycles to actually realize them in code." Each gap is found and fixed within hours, which is honest progress, but it points to insufficient pre-ship structural verification.
2. Code quality / cleanliness — 65 / 100
What's working: queued-build-tool discipline gates everything, no em-dashes enforced at file write, CRLF inflation caught and called out, static-grep tests pin invariants (perimeter audits for retired arrays). Build clean four-target reliably. CMake CONFIGURE_DEPENDS catches new files.
What's dragging it: 4 pre-existing test failures in the suite, parked rather than fixed. "Test suite passed" sometimes means "build verified, didn't run full suite." Some commits land without smoke verify on the actual binary (we caught the install-path mismatch in playtest, not in test). Naming consistency is good but fingerprints from the decomp era still surface (g_* mixed with newer conventions). 50+ active worktrees clutter the repo's .claude/worktrees/.
3. Modernity — 55 / 100
What's working: thread pool primitive shipped, parallel verify pass, ImGui menus replacing legacy N64 chrome, GPU swarm benchmark with bot-count testing, modern progress UI, GLSL 4.3 core, P2P + presence + chat layers, structured logging with channel masks.
What's dragging it: mesh data still N64 vertex commands, GBI rendering, custom decoders for everything. The engine modernization vision (PBR, modern physics, modern shader pipeline) is documented as a roadmap but barely touched. Half the runtime path is decomp-era code that works correctly but reads like 1999. The renderer is functional but not modern. No frame profiler, no GPU debug tooling, no asset pipeline that supports modern formats.
4. Stability / playability — 35 / 100
This is the immediate weakness. Today's playtest hit four blockers in one session: build tool ROM placement, Combat Sim modal stuck, weapons load broken (game-breaking), CS room Esc behavior. Stage load AVs have been recurring at the same code paths through three triage cycles (B-318 → B-323 → B-324). The build-test-playtest-find-bugs-build cycle is producing 1-3 follow-up triages per ship.
What's working: the build does boot. The catalog universality is functioning end-to-end on clean install. Audio works. Background levels load. Single-player Campaign does run. The Forge editor exists.
What's dragging it: everything that breaks the playtest experience. Today's weapons-load bug means you can't tell which weapon you have — that's not "polish needed," that's "the game doesn't work right now." The modal-stuck regression means Combat Sim isn't usable. Online doesn't work. Test regression coverage is thin enough that we discover stage-load AVs by playing rather than by CI.
5. Modding ecosystem readiness — 40 / 100

No documented modder workflow. No mod registry. No "modder onboarding" flow. The proper-file-construction commitment is captured but not started. The infrastructure for modding exists; the experience for modders does not.

Where I'd scold us
One: the migration cycle is producing too many discovered gaps. F13 retired g_Weapons[] assuming .pdbase was the runtime path. Step 5 retired .pdbase. Neither step verified the next layer was ready. BYOR completion fixed one half of the resulting hole. B-318 → B-323 → B-324 fixed three more. We're discovering structural gaps via crashes instead of via pre-migration audits. The pattern says: before retiring a layer, the audit must trace EVERY consumer of that layer to its replacement and prove it's wired. That audit happened informally; it needs to be rigorous and signed.
Two: ship gates are too lenient. "Build clean four-target" is necessary but not sufficient. We need "headless smoke-verify clean-install boot to title screen + Combat Sim entry + weapon equip" as a CI gate before any merge that touches catalog/load/render paths. Until that's in place, every playtest will surface bugs that should have been caught at build time.
Three: online has been stubbed for too long. The infrastructure has been "ready" for weeks but the user-facing experience is broken. Every release demonstrates the layers init-ing successfully, then doesn't actually let users play together. This is the single biggest gap between "fascinating engineering project" and "thing my friend actually plays."
Four: the parked-thread sprawl is a planning debt. 100+ sessions, dozens parked, multiple competing pillars active simultaneously. After stability lands, you're going to have to make hard sequencing calls about which 2-3 pillars get attention next. The kanban with priority flags helps but doesn't substitute for an executive "this quarter we're doing X, Y, Z, everything else waits" decision.
Five: a fair amount of polish and recovery work happens because the playtest discovers the issues. That's a feedback loop with an artificially long delay (build → install → run → see crash → report → triage → fix). Tightening that loop with automated playtest scripts (input replay over a stable scenario) would catch regressions in seconds instead of in the field.

Where credit's due
Catalog universality is genuinely well-engineered. Per-asset files, BYOR-compliant, walker-as-sole-source, no shortcuts shipped. The Option B uniform pattern across metadata kinds is the architecturally correct shape and you fought for it (twice).
The principles are durable. "No half-measures," "migrate-first-then-fix-structurally," "BYOR is a constraint not a tradeoff," "kanban with context same commit," "complete unit shipping" — these aren't aspirations, they show up in every spawn brief and they get applied. The memory system carrying these forward across sessions is genuinely effective.
Documentation discipline is uncommon for an indie project. Audits, design docs, daily logs, weekly super audits, file:line evidence, post-ship audit appends. This is platform-team discipline.
Velocity-when-it-flows is high. Catalog migration end-to-end in a week. Three startup-acceleration phases in a day. Multi-session concurrent work works.
Sessions self-report context state. The "fresh / mid-flight / deep / handoff-recommended" contract is a real innovation — most multi-session systems don't have that visibility.
The Combat Sim binding spec → universal grammar synthesis is excellent design work. Short, principled, and cross-referenced to actual screen behavior. That doc will be load-bearing for years.

Single most valuable next move
Build the headless smoke-verify gate. Specifically: a CI script that drops the binary in a clean install, runs it for 30 seconds with a scripted input sequence (boot → title → Combat Sim → equip Falcon 2 → exit), and asserts no AV + log lines for LOADER.UNIVERSAL.SUMMARY: registered > 0 for all kinds + weapon-equip event captured. Add that as a pre-merge gate.
If that gate had existed yesterday, today's four playtest blockers would have been caught at build time.
This is one focused session of work and it lifts the stability score AND the execution-quality score simultaneously. After it's in, the rest of the roadmap moves faster.
