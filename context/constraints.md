# Constraints Ledger

## Purpose
This file tracks what we must respect (active constraints) and what we've intentionally abandoned
(removed constraints). Before implementing anything complex, check whether the complexity comes
from a constraint that has already been removed.

---

## Active Constraints

These are things we must still respect:

- **Save file format compatibility**: Config values stored in `pd.ini` via configRegisterInt/UInt. Save migration framework (SAVE_VERSION) exists for future format changes.
- **MPSETUP_VERSION**: Public constant in `port/include/mpsetups.h`. Currently **v2** (2026-04-26: bumped from v1 alongside `NET_PROTOCOL_VER 43 -> 44` for the Goldfinger 64 weapon cull). v < 2 saves migrate via the clamp rule in `mpsetupfileLoadWad` (`src/game/mplayer/mplayer.c:4474-4493`): weapon values >= 0x27 (the old PP9I slot) are clamped to `MPWEAPON_DISABLED` (now 0x28, formerly 0x30), and the random-filter mask is cleared. **The constant lives in the public header** (not file-local in `port/src/mpsetups.c`) so the test pin (`tests/test_versions_pin.c`) can read the live value through the public header. Promoted 2026-04-26.
- **Shipping scope: in-client online connectivity only (S486, 2026-04-27; updated 2026-05-21)**: The current release target is online connectivity inside the game client, not the standalone dedicated server product. Prioritise listen-host flow (`g_NetDedicated == 0`), client join, rooms/lobby, connect codes/NAT path, manifest/catalog distribution, ready gate, stage transitions, reconnect, and in-client UX. The standalone `pd-server` / `PerfectDarkServer.exe` target is removed/deprecated and must not be used for routine verification; game-agnostic broker work (`P4-B/P4-C`, `server_stubs.c` shrink, plugin ABI) is deferred and must not block client-hosted online shipping work.
- **Net.Server.Port (pd.ini)**: Default listen-server UDP port for in-client hosting (`pdgui_menu_network` “Host game”). CLI `--port` still overrides in `netInit()` after config load.
- **Sentinel-audit discipline + `spawnWeaponNumIsResolved` (S483c, 2026-04-27, B-263)**: When introducing a new reserved-value sentinel into a field that already has consumer-side checks, the audit MUST update EVERY consumer of the field, not just the writer that produces the new sentinel. The FIESTA-mode crash (B-263) shipped because `SPAWNWEAPON_FIESTA_SENTINEL = 0xFE` was added cleanly to `matchStart`'s writer (S482) but downstream consumers in `setup.c` kept the legacy `!= 0xFF && != 0` exclusion that the new sentinel was not designed to satisfy -- 0xFE flowed into `modelmgrLoadProjectileModeldefs(254)` and indexed `g_Weapons[254]` past the end of an 86-entry array. The defence is centralisation: `port/include/net/matchsetup.h::spawnWeaponNumIsResolved(num)` is the SINGLE source of truth for "is this a real resolved WEAPON_* enum?" -- returns 0 for {0, 0xFF, 0xFE}, 1 otherwise. EVERY consumer of `g_MatchConfig.spawnWeaponNum` outside the writer (`matchStart`) and the explicit FIESTA-branch sites (`bot.c::botSpawn`, `player.c::playerSpawn` first conditional) MUST gate on this helper; consumers that previously open-coded `(num != 0xFF && num != 0)` are migrated. Defence in depth: leaf-side consumers that use the field as an array index MUST validate against the array bound and emit a `WEAPON.SLOT.MISS:` LOG_WARNING on miss (INV-1 loud-fail discipline) -- this catches a future caller that bypasses the upstream gate (wire-data tampering, not-yet-migrated consumer, race). Tests in `tests/test_spawn_weapon_resolved.cpp` lock the helper contract with an exhaustive 0..0xFF walk so any future sentinel addition that drifts the helper fails the test rather than crashing in production. Adding a new sentinel = update {1} the writer site, {2} `spawnWeaponNumIsResolved`, {3} the test's reserved-set list. Added 2026-04-27.
- **Model rodata-validity guard + load-time tree probe (S483b, 2026-04-27, B-261)**: The model relations-update tree (`modelUpdateReorderRelations`, `modelUpdateDistanceRelations`, `modelApplyDistanceRelations`, `modelApplyToggleRelations`, `modelApplyReorderRelationsByArg`) MUST probe `node->rodata` for full-struct readability via `modelRodataIsReadable(rodata, sizeof(<variant>))` BEFORE any deref, and BEFORE `modelGetNodeRwData` (which itself reads `rodata->*.rwdataindex`). Misses go through `modelRodataLogMiss` which emits a rate-limited `MODEL.RODATA.MISS:` warning -- channel name parallels INV-1's `CATALOG.MISS:` discipline (b6a0c280). The probe is a `VirtualQuery`-based addressability check on Windows; non-Windows degrades to NULL check. Load-time companion: `setupLoadModeldef` (the chokepoint for all prop / weapon / hat / projectile model loads) calls `setupValidateModeldefRodata` after `modeldefLoadToNew` succeeds; the validator walks the rootnode tree once and logs `MODEL.RODATA.LOAD: PARTIAL modelnum=<N> ...` if any node's rodata is unreadable. The diagnostic surfaces partial-load conditions (Mike's catalog-data-missing hypothesis from the 04:21 LVTICK 1836 AV) at load time so they can be discriminated from runtime corruption. Helper lives at `port/src/model_rodata_guard.c` + `port/include/model_rodata_guard.h`; the header returns `int` rather than `bool` so it remains includable from `src/lib/model.c` without colliding with the `bool = s32` macro from `types.h`. Any new rodata-reading update function added to the relations-update tree MUST gate on `modelRodataIsReadable` first or it inherits the AV class B-261 documents. Added 2026-04-27.
- **Spawn-weapon Random/Fiesta pool source (S483, 2026-04-27)**: Random and Fiesta spawn-weapon modes draw their eligible pool from the host's match-manifest `MANIFEST_TYPE_WEAPON` entries, NOT from `g_MpSetup.weapons[0..5]`. The host builds the manifest pool in `s_manifestAppendWeaponPool` (`port/src/net/netmanifest.c`) by walking `assetCatalogIterateUnlockedByType(ASSET_WEAPON, ...)` and filtering NONE/DISABLED/SHIELD. The pool is broadcast to clients via the existing `SVC_MATCH_MANIFEST` machinery -- no new wire fields, no protocol bump. At spawn time both host and clients call `spawnWeaponPickFromMatchManifest` (`port/src/net/matchsetup.c`) which cascades through `g_CurrentLoadedManifest` / `g_ServerManifest` / `g_ClientManifest` and falls back to `spawnWeaponPickFromActiveSet` when no manifest is loaded (e.g. solo CS). Mod-only weapons distribute via the existing `SVC_CATALOG_INFO` -> `CLC_CATALOG_DIFF` -> `SVC_DISTRIB_*` pipeline at lobby join (ASSET_WEAPON is already in the `netmsgSvcCatalogInfoWrite` type list). Spawn-site fallback discipline: never spawn a player empty-handed -- if both pools are empty matchStart() RANDOM uses `MPWEAPON_FALCON2` with a WARNING; FIESTA falls into the existing `resolvedWeaponNum=0` miss path that the player/bot loops already handle.
- **ENet protocol version**: Must match across clients. Currently **v49** (`port/include/net/net.h:12`). Mixed-version play is rejected at ENet auth (`netServerEvConnect`) and presence proto checks. Recent ledger: v49 adds `CLC_LOBBY_RESYNC 0x18` so post-match room return can request authoritative `SVC_ROOM_ASSIGN` + `SVC_ROOM_SETTINGS` + `SVC_ROOM_PLAYLIST`; v48 adds `SVC_GPUSWARM_STATE 0x6c`; v47 adds `surface_up` locomotion sync on NPC/bot movement; v46 adds mandatory SHA-256 digest on `SVC_DISTRIB_BEGIN` plus cutscene network semantics (`SVC_CUTSCENE`, `CLC_CUTSCENE_SKIP` bound to authenticated client state); v45 adds spawn-weapon mode wire fields; v44 is the fresh-build hygiene bump for the Goldfinger weapon + AllInOne arena cull; v43 adds `SVC_PLAYER_STATS.attacker_id`; v37 removes raw `chrslots`; v32 makes scenario identity a catalog ID string; v31 makes prop model identity a catalog session ref; v30 makes weapon identity a catalog session ref; v27 removes `net_hash` from wire. No integer asset identity may appear on the wire.
- **30 agent save slots**: Hardcoded in filelist struct layout. Cannot increase without breaking save format.
- **Participant pool (g_MpParticipants)** is the sole store of match slot state (B-12 complete). Players occupy slots 0..MAX_PLAYERS-1, bots occupy MAX_PLAYERS..MAX_MPCHRS-1. Use `mpIsParticipantActive(i)`, `mpAddParticipantAt(slot, type, team, client_id, localslot)`, `mpRemoveParticipant(slot)`, `mpGetActiveBotCount()`, `mpGetActivePlayerCount()`. The wire encode/decode helpers are `mpParticipantsEncodeActiveMask()` / `mpParticipantsDecodeActiveMask()`. - **PLAYERCOUNT()**: Returns number of local human players (1-4), not total chrs.
- **ROM data files**: Model/animation files come from ROM dump. Models not in ROM return NULL from fileLoadToNew (fixed Session 13). Mod content extends via mod loader.
- **`bool` is `s32`, not `_Bool`**: Defined in `types.h` and `data.h` as `#define bool s32`. **Never include `<stdbool.h>`** in game code — it redefines `bool` to `_Bool` and causes type conflicts. New game headers should include `"types.h"` to get `bool`.
- **C11 game code / C++ port code**: Game logic in C11, port/renderer in C++. Must not introduce C++ in `src/game/` or `src/lib/`.
- **CMake + MinGW/GCC on Windows**: User compiles on Windows. AI cannot compile — code must be reviewed for correctness before delivery.
- **ENet statically linked**: Along with SDL2, zlib, and libcurl.
- **60 Hz tick rate**: Game logic runs at 60 ticks per second. Network sync frequencies are multiples of this.
- **Name-based asset resolution only**: All asset references must use full catalog ID strings resolved through the Asset Catalog. Catalog IDs must be human-readable identity in `[namespace]:[asset_type]_[name]` form, such as `base:weapon_falcon2`, `base:sfx_rocket_launch`, `base:model_falcon2_hi`, or `mod_my_pack:sfx_custom_reload`. Numeric ROM addresses, table indices, file numbers, sound IDs, model IDs, body/head numbers, animation slots, and array offsets are not asset identity and must not appear in catalog IDs or authored asset-reference fields. Existing numeric runtime fields are migration debt only, not an accepted internal catalog reference model. Updated 2026-05-22.
- **Catalog ID strings for all asset references**: All asset references everywhere (wire protocol, save files, public APIs, manifests, config, runtime structs, tool UI, authored archives, dependency descriptors, source files, and generated live files) must use full human-readable catalog ID strings. `net_hash` and other compact numeric references are deprecated and must not be used anywhere. Raw N64 array indices (`bodynum`, `headnum`, `filenum`, `stagenum`, `texnum`, `animnum`, sound slots, model slots, etc.) must not cross an asset-reference boundary and must not be presented as catalog identity. Added S90; upgraded to no-net_hash mandate 2026-04-02; strengthened to all asset references 2026-05-22.
- **Asset references use catalog ID strings everywhere**: ALL asset references use the catalog ID string format `[namespace]:[asset_type]_[name]`. This applies to bodies, heads, stages, weapons, models, meshes, SFX, voice, music, textures, animations, UI, fonts, language banks, projectiles, entities, nested dependencies, and future asset families. No exceptions. Added 2026-04-02; broadened 2026-05-22.
- **matchslot/match config: catalog ID strings are identity**: The `matchslot` struct stores `body_id` and `head_id` as catalog ID strings. `mpbodynum`/`mpheadnum`/`bodynum`/`headnum`, `weapons[]`, `spawnWeaponNum`, and `scenario` are deprecated migration fields when still present; they are not asset references and must not be used as identity. New match setup, save, wire, manifest, or runtime code uses catalog IDs directly. Added 2026-04-02, updated 2026-04-06, 2026-04-07, and strengthened 2026-05-22.
- **Catalog-first pattern for stage identity (UNIVERSAL — all flows)**: `g_MissionConfig.stage_id` is the authoritative stage identity throughout all mission flows. `stagenum` (integer) is ONLY resolved from `stage_id` at the exact point of consumption (e.g., just before calling `mainChangeToStage()`). Never store a stagenum integer and pass it around — store the catalog ID. Never call `mainChangeToStage()` with a hardcoded or locally-computed stagenum — always resolve from `stage_id` via `catalogResolveStage()`. This pattern applies to: mission select, match start, stage transitions, lobby, solo, MP, endscreen restart — EVERY flow. Added 2026-04-06 (S165 — B-119 stagenum=0x00 crash fix). - **Catalog registers ALL assets (unlock is a separate layer)**: The catalog must register every asset that exists, including SP-only heads and bodies. Whether an asset is available to a player in MP is a gameplay/unlock decision — it is NOT a catalog registration decision. The head registration loop in `assetcatalog_base.c` must iterate ALL entries in `g_HeadsAndBodies[]`, not just MP-reachable ones. The MP character selection UI checks unlock status to filter what is shown; the catalog does not filter. SP-only characters unlock for MP when: the player has beaten the mission where that character appears, OR the Unlock All cheat is active. Added 2026-04-02.
- **Catalog-owned asset lifecycle (S485, 2026-04-27; strengthened 2026-05-22)**: The catalog is the single source of truth for declared asset identity, metadata, references, source handles, dependencies, load state, loaded payloads, refcounts, and release/unload behavior. Static Layer A tables (`g_Weapons`, `g_MpWeapons`, `g_Stages`, `g_ModelStates`, `g_HeadsAndBodies`, etc.) are migration sources only, not identity stores or asset-reference surfaces. Public, save, wire, manifest, config, runtime, tool, and authored-archive boundaries use catalog ID strings. Numeric legacy slots may remain temporarily as private loader/runtime metadata while being retired, but they are not catalog IDs, not internal asset references, and not acceptable names for generated live files. Stage/screen manifests drive lifecycle by retaining/releasing catalog assets by catalog ID, not by independently loading raw files or resolving numeric handles.
- **Typed asset archives are self-contained on disk (2026-05-21, c3812/c3814)**: Every typed `*.pdxxx` asset archive is the sharing/modding source unit and must embed all authored dependencies needed to edit, clone, share, and load that asset: descriptors, meshes, materials, textures, rigs, animation targets, audio, language/font/map tables, nested projectile/entity/behavior payloads, and any equivalent future authored payloads. Cross-asset duplication on disk is allowed. Catalog build/load may canonicalize duplicate inner assets by SHA-256 and catalog identity to avoid RAM/runtime duplication after ingestion, but dedupe must not turn asset archives into reference-only shells. `.pdmod` remains transport only; private generated cache stays rebuildable and unshipped.
- **Public asset source is the game-facing source (2026-05-25, c3842)**: Every asset family must expose user-editable standard/source files in the public authoring zone, and the game client must consume those same files natively through the catalog/provider loading pipeline. Private renderer, GPU, collision, audio codec, animation, graph, or other engine-ready products may be generated for speed, but they are source-hashed rebuildable cache, not parallel authored payloads and not a required hand-maintained duplicate. If native use requires conversion, the converter/importer/cache path is part of the asset pipeline and must preserve round-trip authoring instead of shipping opaque `.bin` or preprocessed dumps. This applies equally to base-game and mod assets.
- **No numeric asset references in public typed archives (2026-05-25, c3842)**: Public typed-archive descriptors, setup/source tables, behavior graphs, dependency manifests, and generated example assets must use catalog ID strings for asset references. Fields such as `model_id`, `modelnum`, `filenum`, `weapon_id`, `sound_id`, `texnum`, or legacy symbols like `MODEL_*`/`FILE_*` are not acceptable authoring references; if retained at all, they belong only in private migration metadata that cannot be consumed as source identity.
- **No raw setup word dumps in public typed archives (2026-05-25, c3841)**: Public authoring zones must contain immediately understandable source files, not preprocessed word dumps or byte-table diagnostics. `setup.tsv`, `mpsetup.tsv`, and similar raw `offset/u32/s32/f32/ascii4` exports are migration-only forensic artifacts and must not be accepted as the final `.pdscenario` or `.pdmission` authoring contract. Scenario setup, mission flow, objective state, triggers, globals, and AI/script behavior must decode into named tables and graph assets that can round-trip back to runtime data.
- **Scenario mesh/collision/nav source contract (2026-05-25, c3841)**: `.pdscenario` owns one user-facing level scene source, preferably `scene.glb` or `scene.gltf` with embedded or archive-local buffers/textures. An optional explicit collision override, such as `collision.glb` or `collision.obj`, may be present. When absent, runtime collision is deterministically generated from the level scene using declared import rules. Bot navigation is generated deterministically from scenario geometry/collision plus gameplay volumes and must support the PC movement extensions, including jump links and wall/ceiling traversal data for wall-running bots, instead of relying on opaque legacy waypoint dumps.
- **Textured scene source is the runtime scenario source (2026-05-25, c3841)**: `scene.glb`/`scene.gltf` must open in Blender and 3DS Max with the expected mesh hierarchy, UVs, materials, and textures without project-specific plugins. `scene.glb` is preferred for shipped examples because it can embed buffers and textures; `scene.gltf` is allowed when all external buffers/textures are archive-local and referenced by relative paths. The game scenario loading pipeline must consume that same source through the catalog/provider path. Private renderer, collision, room, portal, and navigation products may be generated for speed, but they are rebuildable cache invalidated by source hashes, not separate authored requirements.

- **`manifestClear` before `mainChangeToStage` during MP teardown**: Any callsite that changes stage while an MP match's `g_ClientManifest` still has entries MUST call `manifestClear(&g_ClientManifest)` first, or `mainChangeToStage()`'s `manifestMPTransition()` branch will diff the torn-down manifest against whatever is loading and access-violate. Known required sites: `pdgui_bridge.c:799` (`pdguiEndscreenExitToMainMenu`, F-0.4), `netmsg.c:1419` (`netmsgSvcStageEndRead`, L1-1), `net.c::netDisconnect` (Bug A, 2026-04-13). New callsites that change stage while holding an MP manifest MUST replicate the pattern. See [systemic-bugs.md](systemic-bugs.md) SP-13. Added 2026-04-13 (Bug A fix, commit `d37e9677`).
- **`mods/` tree depth is capped at two levels**: Discovery scanners (`modmgrScanDirectory`, `s_scanModChromeStyles`, `scan_mods_for_themes`) recurse **exactly one level** into any top-level entry that has no manifest (`mod.json`/`audio.ini`/`theme.json`) — supporting category folders like `mods/UI Chrome/<slug>/`, `mods/Weapons/<slug>/`, `mods/MP Maps/<slug>/`. Do not remove the depth cap; deeper recursion would walk arbitrary user-created trees and create surprising discovery behavior. When adding new mod-discovery scanners, replicate the same `register-or-recurse-once` pattern (see `modmgrTryRegisterModEntry` + `modmgrScanCategoryFolder` in `port/src/modmgr.c`). Nine-Slice Chrome tool saves to `mods/UI Chrome/<slug>/`. Added 2026-04-16 (S293).
- **`matchConfigMaxBotsForHumans(humanCount)` is the single-source-of-truth for bot cap**: All callers that compute the maximum bot count for a match MUST pass the actual human count — never hardcode `1`. The canonical helpers are `matchConfigCountHumans()` (counts SLOT_PLAYER in `g_MatchConfig`, min 1) when no external count is available, or the lobby-aware count (e.g. `scenario_save.c` passes the parsed `humanCount`, `pdgui_menu_room.cpp` uses the room's human count). SVC_ROOM_SETTINGS client rebuild must also use the same `matchConfigChooseBotTeam()` helper as the host for team assignment, to keep host/client slot views consistent. Added 2026-04-16 (S294 — B-144 fix).
- **Ready gate lifetime is bound to its room's lifetime**: When a room holding an active ready gate (`s_ReadyGate.room_id == room->id`, `s_ReadyGate.active == 1`) is destroyed, or when any client in `s_ReadyGate.expected_mask` leaves the room or disconnects, the gate must be aborted via `readyGateAbort()` so that `SVC_MATCH_CANCELLED` is broadcast and clients clear their countdown UI. The canonical hooks are in `roomLeave()` (`port/src/room.c`); `readyGateTickCountdown()` also carries a defensive "room missing" check. Added 2026-04-14 (Bug B fix).
- **MP scenario stage-load reset is match-stage owned (B-342, 2026-05-18)**: `lvReset()` must not call raw `scenarioReset()` for every stage load. The stage-load path uses `scenarioResetForStageLoad(stagenum)`, which allows MP scenario intro parsing only when the loaded stage matches the active match setup stage (`g_MpSetup.stagenum`). Do not "fix" mission-load crashes with `!g_Vars.normmplayerisrunning` early returns inside the scenario lifecycle; drop-in/drop-out multiplayer can pass through transitional states where the match setup already owns the stage before every legacy runtime flag is settled.
- **Dynamic prop collision meshes detach before stage-pool reset (B-343, 2026-05-18)**: `prop->colmesh` is heap-owned collision data hanging off props allocated from `MEMPOOL_STAGE`. Any reset path that calls `mempResetPool(MEMPOOL_STAGE)` must call `meshDetachAllStageProps()` first while the live prop list is still valid. `meshDetachAllStageProps()` must walk `g_Vars.activeprops` with a `maxprops` visit cap, not every raw slot in `g_Vars.props`, because unallocated free-list tail slots may contain stale stage-pool bytes. `varsReset()` must initialize every prop slot's `colmesh` to NULL and terminate the free-list tail. Do not detach prop meshes from `lvReset()` after setup load; by then the previous stage prop pool may already have been recycled.
- **Menu pool is the structural dedup layer for menu types**: `port/include/menupool.h` + `port/src/menupool.c` define a pre-allocated `s_Pool[MENU_TYPE_COUNT]` keyed by `menu_type_t`. `menuPushDialog()` consults the pool after the F-3.1 pointer-scan; denial is structural (returns without mutating g_Menus[]). The `nextsibling` auto-open loop consults `menupoolIsDialogActive(sibling)` and skips any sibling whose type is already active elsewhere. `menuCloseDialog()` releases every sibling's pool slot. Force-close sites (`pdgui_bridge.c` endscreen paths, `matchsetup.c` match start, `netmsg.c` stage handlers, `inputCtxShutdown()` nuclear reset) call `menupoolReleaseAll()` for bulk teardown. Several dialogdefs may map to the same type (PC + Pause main menu variants → `MENU_TYPE_MAIN_MENU`; arena/scenario/weapons/limits → `MENU_TYPE_MP_SETUP`). Unregistered dialogdefs pass through with no dedup (legacy-safe). The pool also supports optional input-context ownership via the `ctx` parameter of `menupoolAcquire` — reserved for future migration of the `s_*PushedCtx` pattern in ImGui renderers. See ADR `context/designs/input-authority-and-menu-pool-2026-04-13.md` §6. Added 2026-04-16 (S299 Phase 2).
- **Lifts must be registered in `g_Lifts[]` at stage-setup time**: `liftActivate(prop, liftnum)` registers a lift prop in the global `g_Lifts[10]` array keyed by `pad.liftnum`. Without the registration, `liftFindByPad()` returns NULL and stepping on a lift pad does nothing. The historical caller was only the AI-script command `aiActivateLift` (opcode `0x018d`, `src/game/chraicommands.c:8498`), which meant CI arenas (no AI scripts) had dead lifts. Fix lives in `src/game/setup.c::OBJTYPE_LIFT` -- auto-registers by reading `liftnum` from `PADFIELD_LIFT` on any of the lift's own pads. SP remains correct because the AI-script call writes the same pointer (idempotent). Any new MP map with a lift MUST have a valid `lift->pads[]` entry with a non-zero `liftnum` in pad data. Added 2026-04-17 (S310).
- **`romProviderHandle()` is internal to the catalog/provider layer** (Phase 4, S346/S496, 2026-04-17/2026-04-28): Game code (`src/game/`) must NEVER call `romProviderHandle()` or include `assetprovider_internal.h`. The allowed callers are `assetload.c`, `assetcatalog_api.c`, `assetcatalog_base.c`, `assetcatalog_base_extended.c`, `server_stubs.c`. For ROM file loads, game code uses `assetLoadRomToNew(filenum, method, loadtype)` (declared in `assetload.h`) or `fileLoadToNew(filenum, method, loadtype)` (declared in `game/file.h`). For stage file handles, game code reads from `catalog_stage_result_t` fields (`bg_handle`, `pads_handle`, `setup_handle`, `mpsetup_handle`, `tile_handle`). For body/head handles, game code uses `catalogGetBodyHandle()` / `catalogGetHeadHandle()` or typed resolve results. For `MODEL_*` / `g_ModelStates[]` modelnum loads, game code uses `catalogResolveModelByModelnum()` / `catalogGetModelHandle()`; `catalogGetPropHandle()` remains only as a compatibility wrapper. The SA-5a bridge functions (`catalogGetBodyFilenumByIndex` etc.) are `[DEPRECATED]` — only still present for callers of legacy APIs that require a raw filenum (e.g., `fileGetInflatedSize`, `modeldefLoad`).
- **Identity cookie is the reconnect authority (MASTER-C3, S393, 2026-04-19)**: `struct netpreservedplayer` records both `name` and a 16-byte `cookie[NET_AUTH_COOKIE_LEN]` server-issued at first `CLC_AUTH`. Reconnect to a preserved slot requires `netServerFindPreservedByCookie(name, cookie)` to match BOTH fields in constant time. Legacy name-only lookup (`netServerFindPreserved`) remains for advisory/diagnostic use but MUST NOT be used to gate a preserved-slot restore. Any future path that touches preserved-player state must use the cookie-gated accessor. Client-side cookie is module-static in `netmsg.c` and is cleared on `netDisconnect` — never persist cookies to disk.
- **Persistent bans live in `$S/bans.ini`, consulted in `netServerEvConnect` (MASTER-C2c/C2d, S393, 2026-04-19)**: `serverBansInit()` runs once at server start, after `hubInit()`. `netServerEvConnect` calls `serverBansIsBanned(ip)` before any client slot allocation — banned peers receive `DISCONNECT_BANNED` immediately. Adding a ban via `serverBansAdd` (or `netServerBanClient`) saves the file atomically. Bans are NOT replicated across servers — each operator's `$S/bans.ini` is independent.
- **Admin RCON token is hashed, never stored as plaintext (MASTER-C2a, S393, 2026-04-19)**: `serverAdminInit(cliToken, iniToken)` runs once at server start with tokens from `--admin-token` (CLI) or `[Admin] Token` (server.ini) — CLI wins. Tokens shorter than 16 characters are rejected (boot warning if accepted length is below recommended 32). `serverAdminVerifyToken` does constant-time compare against the stored SHA-256 (domain-salted `"pd2-server-admin-token-v1\n"`). Once `serverAdminInit` returns, all plaintext token memory on the caller's stack MUST be zeroed.
- **Room passwords are hashed at create time (SEC-14, S393, 2026-04-19)**: `roomCreateConfigured` accepts a plaintext password and immediately feeds it through `roomHashPassword` (domain-salted `"pd2-room-password-v1\n"` SHA-256) before storing. The plaintext is discarded. `roomCheckPassword(room, plaintext)` is the sole matcher — constant-time compare against `room->password_hash`. Open rooms have an all-zero hash and `roomCheckPassword` returns 1 for them unconditionally.

## Removed Constraints

These constraints have been explicitly abandoned. If a task involves working around one of these, **stop and propose the simpler approach**.

- **2026-03-01: N64 platform guards** — PC-only target. All 672 `PLATFORM_N64` guards stripped across 114+ files. Zero references remain. (Phase D1 complete)
- **2026-03-01: 4MB memory mode** — `IS4MB()` is compile-time `0`, `IS8MB()` is compile-time `1`. Compiler eliminates all 4MB branches. `g_Is4Mb` variable removed.
- **2026-03-01: N64 dead code** — All N64 assembly (.s), ultra/os, ultra/libc removed. Only ultra/audio, ultra/gu, and 4 ultra/io vi mode files remain.
- **2026-03-05: N64 micro-optimization** — Modern x86_64 HW. Prefer correctness over cycle-counting. Hand-rolled sorts, manual bit-packing, fixed-point math — replace with standard approaches.
- **2026-03-10 / superseded 2026-04-27: Dedicated-server-only shipping model** — Historical Phase D9 moved toward a dedicated-server-first model. S486 supersedes that as a release constraint: the current ship target is in-client online connectivity/listen hosting, with dedicated server work deferred to a future track.
- **2026-03-12: N64 collision workarounds** — Legacy cdTestVolume/cdFindGroundInfoAtCyl hacks replaced by capsule sweep system (capsule.c). Use proper geometric solutions.
- **2026-03-15: 4-player bot limit** — Original N64 supported ~8 bots max. PC port supports up to 31 bots + 1 player = 32 total (participant pool). `MAX_BOTS=32` (S45, was 24), `chrslots u64` (S45, was u32). Pool sizes expanded (Session 17): NUMTYPE1=70, NUMTYPE2=50, NUMTYPE3=48, NUMSPARE=80, weapons=100, hats=20, ammo=40, debris=30, projectiles=200, embedments=160.
- **2026-03-18: N64 body/head restriction in MP** — `mpGetNumBodies` unrestricted. Full 63+ character roster available in network play.
- **2026-03-20: `--log` CLI flag requirement** — Logging is now unconditional (always on). Log filename depends on mode: pd-server.log, pd-host.log, pd-client.log.
- **2026-03-23: Shared memory pools for mods** — N64-era pre-allocated pools (modconfig.txt `alloc` values) replaced by dynamic `malloc`-based allocation. Each component manages its own memory. Advisory `hint_memory` field in `.ini` for UI display only.
- **2026-03-23: Monolithic mod structure** — Mods are no longer single directories loaded/unloaded as a unit. Replaced by component-based architecture where each asset (map, character, skin, etc.) is an independent folder with its own `.ini` manifest. See [component-mod-architecture.md](component-mod-architecture.md).
- **2026-03-23: Numeric asset lookups** — ROM addresses, table indices, and array offsets for asset identity are abandoned. All asset references go through the string-keyed Asset Catalog. This eliminates the root cause of B-13 (scale), B-17 (stage ID mismatch), and the entire class of index-shift bugs when mods change.
- **2026-03-24: g_ModNum integer mod selector** — `g_ModNum` (0=Normal, 1=GEX, 2=Kakariko, 3=DarkNoon, 4=GF64) fully removed. MOD_NORMAL/MOD_GEX/etc. constants removed. Asset Catalog is sole mod authority. (D3R-11, S45)
- **2026-03-24: modconfig.txt parsing** — `modConfigLoad()` and all parsing logic removed. Mods require `mod.json`. Dirs without `mod.json` are skipped by `modmgrScanDirectory`. (D3R-11, S45)
- **2026-03-24: Shadow asset arrays** — `g_ModBodies[]`, `g_ModHeads[]`, `g_ModArenas[]` static shadow arrays in modmgr.c removed. Catalog-backed caches (`s_CatalogBodies/Heads/Arenas`) are the only backing store. (D3R-11, S45)
- **2026-03-24: fileSlots 2D array** — `fileSlots[5][ROMDATA_MAX_FILES]` (per-mod file slot banks) flattened to `fileSlots[ROMDATA_MAX_FILES]`. Only slot 0 was ever active. (D3R-11, S45)
- **2026-04-02: net_hash wire format** — u32 CRC32 compact references (`net_hash`) are fully deprecated. All wire messages, save files, and APIs must use full catalog ID strings. The hash was an optimization that creates indirection away from actual asset identity and makes debugging harder. Do not introduce any new net_hash fields.
- **2026-04-02: Legacy N64 menu system** — `menuPush`/`menuPop` stack in `menumgr.c` is deprecated. ImGui menus (`pdgui_menu_*.cpp`) are the sole menu system. The legacy stack will be stripped entirely; do not add new entries to it or rely on its state.
- **2026-04-02 / strengthened 2026-05-22: Integer-native match config** — `matchslot` struct no longer treats `mpbodynum`/`mpheadnum` as primary identity. Catalog ID strings (`body_id`/`head_id`) are identity. Integer match fields are migration debt only and must not be passed through match config APIs or treated as a legacy handoff target.
- **2026-04-17: `chrslots` bitmask + `BOT_SLOT_OFFSET`** — B-12 Phase 3 removed the `u64 chrslots` field from `struct mpsetup` along with the `BOT_SLOT_OFFSET`, `CHRSLOTS_PLAYER_MASK`, and `CHRSLOTS_BOT_MASK` constants. The participant pool (`g_MpParticipants`) is the sole source of match slot state on both client and server. Wire protocol bumped to v37 (`SVC_STAGE_START` now carries a derived active-slot mask instead of the raw field). The legacy shims `mpParticipantsToLegacyChrslots` / `mpParticipantsFromLegacyChrslots` + `MpParticipant.legacy_slot` field are gone. If a task feels like it wants to read or write a chrslots bit, use `mpIsParticipantActive(i)` / `mpAddParticipantAt(...)` / `mpRemoveParticipant(...)` instead. Bot slots live at `MAX_PLAYERS..MAX_MPCHRS-1`.

## Index Domain Warning

Three separate index spaces exist and must not be confused:

| Domain | Array | Size | Valid Range |
|--------|-------|------|-------------|
| Stage table index (`g_StageIndex`) | `g_Stages[87]` | 87 | 0–86 |
| Solo stage index | `g_SoloStages[21]` / `besttimes[21][3]` | 21 | 0–20 |
| Stagenum | Logical ID (e.g., 0x5e) | N/A | Arbitrary |

Mod stages have stage table indices 61–86 but **no** solo stage index. Flowing a stage table index into `g_SoloStages[]` or `besttimes[]` is an OOB access. Phase 1 safety guards added (Session 23). Phase 2 will add `soloStageGetIndex()` lookup.
