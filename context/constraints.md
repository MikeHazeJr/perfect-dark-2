# Constraints Ledger

## Purpose
This file tracks what we must respect (active constraints) and what we've intentionally abandoned
(removed constraints). Before implementing anything complex, check whether the complexity comes
from a constraint that has already been removed.

---

## Active Constraints

These are things we must still respect:

- **Save file format compatibility**: Config values stored in `pd.ini` via configRegisterInt/UInt. Save migration framework (SAVE_VERSION) exists for future format changes.
- **Net.Server.Port (pd.ini)**: Default listen-server UDP port for in-client hosting (`pdgui_menu_network` “Host game”). CLI `--port` still overrides in `netInit()` after config load.
- **ENet protocol version**: Must match across clients. Currently **v43** (v43 (2026-04-25): B-256 structural fix — `SVC_PLAYER_STATS 0x22` gains a trailing `s8 attacker_id` field. Sender resolves `mpPlayerGetIndex(chr->lastattacker)` at write time on the producing peer where chr-data is canonical, or writes `-1` sentinel for non-player attackers (NULL lastattacker, world damage, suicide, out-of-bounds index). Receiver prefers the wire field over the local-resolve fallback when valid (`>= 0` and `!= self`); the v42 third-site closure at `netmsg.c:2128` becomes the fallback path for self-attribution and -1 sentinels. Mixed v42/v43 play is rejected at the ENet auth handshake (`port/src/net/net.c:1560` `enet_peer_disconnect(peer, DISCONNECT_VERSION)`) and at the presence-channel proto check (`group_session.c:212`); receivers never see a v42 packet on a v43 build. v42: Phase 3 wire -- `CLC_SPECTATE_REQUEST 0x16` + `SVC_SPECTATE_ACK 0x6a` + `SVC_STATE_FRAME 0x6b`. Spectator does not consume a player slot: server sets `CLFLAG_SPECTATOR (1<<2)` on the netclient, skips player iteration, and fans out `SVC_STATE_FRAME` at SPECTATOR_FANOUT_HZ = 10 Hz. State frame body: `u32 host_handle` + `u32 frame_seq` + `u8 participant_count` + per-participant 64-byte block. ~10 KB/s outbound per spectator at 16 participants * 10 Hz. Phase 3+ social_share + voice run on dedicated signed UDP sockets (port 27109 PDSHR for listening-room/public-mods/profile, port 27108 PDVOC for opus voice frames) and do NOT participate in the ENet wire. v41: Phase 2 connectivity additive `SVC_ACHIEVEMENT_TOAST 0x69` carries `u32 actor_handle` + utf-8 string up to 96 bytes for authoritative match-host -> all-clients achievement broadcast; receivers route via `pdguiToastEnqueue(TOAST_CATEGORY_SOCIAL)` so the notification mask + per-friend mute apply uniformly. Chat / file-transfer / presence Phase 2 work runs on dedicated UDP sockets, signed via Ed25519, and does NOT participate in the ENet wire. v39: `SVC_ADMIN` response code `ADMIN_RESP_RATE_LIMIT 0x06` for failed `ADMIN_SUB_AUTH` lockout; v38: SEC-7 server-info query 2-stage challenge handshake, MASTER-C3 16-byte identity cookie on `CLC_AUTH`/`SVC_AUTH` + cookie-matching reconnect, SEC-14 room passwords + max_players on `CLC_ROOM_CREATE`/`CLC_ROOM_JOIN`, and `CLC_ADMIN 0x15` / `SVC_ADMIN 0x68` admin RCON; v27: all net_hash removed from wire; v28: SVC_BOT_AUTHORITY + CLC_BOT_MOVE; v29: room networking R-3; v30: weapon identity uses catalog session refs u16; v31: SVC_PROP_SPAWN modelnum uses catalog session refs, bot body/head decode uses runtime_index directly; v32: scenario identity uses catalog ID string on wire — CLC_LOBBY_START, SVC_STAGE_START, server query; v33: A-7 mod audio network sync — SVC_STAGE_START includes mod_track_id, ASSET_AUDIO in SVC_CATALOG_INFO distribution; v34: seamless audio-mod network sync — playlist manifest, per-client DL status, mid-match `SVC_MUSIC_ADVANCE`, catalog rebroadcast (S222 evening batch); v35: L5 match lifecycle — match_seed in SVC_STAGE_START, co-op CLC_LOBBY_START builds manifest + CLC_STAGE_READY, plus additive S253 MP lobby residual — `SVC_ROOM_SETTINGS 0x78`, `SVC_ROOM_PLAYLIST 0x79`, `CLC_ROOM_SETTINGS_UPDATE 0x13`, `CLC_ROOM_PLAYLIST_UPDATE 0x14`; v36: Counter-Op anti-player role is explicit on wire (`antiClientId` in `CLC_LOBBY_START`, anti player slot in `SVC_STAGE_START`), and co-op/anti ready-gate launch uses a single `mainChangeToStage` path; v37: B-12 Phase 3 — the `u64 chrslots` bitmask field is removed from `struct mpsetup` and from `SVC_STAGE_START`. The wire now carries a derived 64-bit active-slot mask computed from the participant pool; the reader decodes it straight into pool entries via `mpParticipantsDecodeActiveMask()`). No integer asset identity may appear on the wire (weapons and models use session catalog u16 refs, scenario uses catalog ID string).
- **30 agent save slots**: Hardcoded in filelist struct layout. Cannot increase without breaking save format.
- **Participant pool (g_MpParticipants)** is the sole store of match slot state (B-12 complete). Players occupy slots 0..MAX_PLAYERS-1, bots occupy MAX_PLAYERS..MAX_MPCHRS-1. Use `mpIsParticipantActive(i)`, `mpAddParticipantAt(slot, type, team, client_id, localslot)`, `mpRemoveParticipant(slot)`, `mpGetActiveBotCount()`, `mpGetActivePlayerCount()`. The wire encode/decode helpers are `mpParticipantsEncodeActiveMask()` / `mpParticipantsDecodeActiveMask()`. Phase 1 (S26) introduced the parallel pool; Phase 2 (S47b) migrated callsites; Phase 3 (2026-04-17) removed the legacy u64 chrslots field + `BOT_SLOT_OFFSET`/`CHRSLOTS_PLAYER_MASK`/`CHRSLOTS_BOT_MASK` constants and bumped the wire protocol to v37. Server now links `src/game/mplayer/participant.c` directly (participant.c is the slot source on both sides).
- **MAX_LOCAL_PLAYERS = 4**: Maximum splitscreen players per machine. MAX_PLAYERS = 8 includes remote. Many arrays sized to these. Participant system uses `localslot` (0-3) per machine, `client_id` per network client.
- **PLAYERCOUNT()**: Returns number of local human players (1-4), not total chrs.
- **ROM data files**: Model/animation files come from ROM dump. Models not in ROM return NULL from fileLoadToNew (fixed Session 13). Mod content extends via mod loader.
- **`bool` is `s32`, not `_Bool`**: Defined in `types.h` and `data.h` as `#define bool s32`. **Never include `<stdbool.h>`** in game code — it redefines `bool` to `_Bool` and causes type conflicts. New game headers should include `"types.h"` to get `bool`.
- **C11 game code / C++ port code**: Game logic in C11, port/renderer in C++. Must not introduce C++ in `src/game/` or `src/lib/`.
- **CMake + MinGW/GCC on Windows**: User compiles on Windows. AI cannot compile — code must be reviewed for correctness before delivery.
- **ENet statically linked**: Along with SDL2, zlib, and libcurl.
- **60 Hz tick rate**: Game logic runs at 60 ticks per second. Network sync frequencies are multiples of this.
- **Name-based asset resolution only**: All asset references must use string IDs resolved through the Asset Catalog. No numeric ROM addresses, table indices, or array offsets for asset identity. The catalog returns runtime indices internally, but no code outside the catalog may hardcode or assume those indices. See [component-mod-architecture.md](component-mod-architecture.md) §5. Added Session 27.
- **Catalog ID strings at all interface boundaries**: All asset references at interface boundaries (wire protocol, save files, public APIs) must use **full catalog ID strings** in `"namespace:readable_name"` format (e.g., `"base:dark_combat"`, `"base:arena_felicity"`). net_hash u32 CRC32 compact references are **deprecated and must not be used anywhere**. Raw N64 array indices (bodynum, headnum, filenum, stagenum, texnum, animnum) must not cross boundaries. Integer indices are resolved from catalog only at the final handoff to legacy engine API. Added S90 (bot config transmission fix; asset reference audit ~180 sites, 20 patterns). Upgraded to no-net_hash mandate 2026-04-02.
- **Asset references use catalog ID strings everywhere**: ALL asset references — bodies, heads, stages, weapons — use the catalog ID string format `"namespace:readable_name"`. This applies to: wire protocol messages (CLC_LOBBY_START, SVC_LOBBY_STATE, SVC_STAGE_START, etc.); save files (scenarios, config); runtime structs (matchslot, match config). No exceptions. Added 2026-04-02.
- **matchslot/match config: catalog ID strings are primary identity**: The `matchslot` struct stores `body_id` and `head_id` as catalog ID strings. `mpbodynum`/`mpheadnum`/`bodynum`/`headnum` integers are derived values resolved from the catalog ONLY when a legacy engine API requires them. Integer derivation uses `catalogGetMpIndex()` at last-mile handoff only. Added 2026-04-02, updated 2026-04-06 (Phase 7: all conversion functions deleted). Updated 2026-04-07 (M0.1c: `weapon_ids[6][64]` and `spawn_weapon_id[64]` added as PRIMARY; `weapons[]` and `spawnWeaponNum` are DEPRECATED derived values resolved at `matchStart()`). Updated 2026-04-07 (M0.1d: `scenario_id[64]` added as PRIMARY; `scenario` (u8) is DEPRECATED derived value resolved at `matchStart()`).
- **Catalog-first pattern for stage identity (UNIVERSAL — all flows)**: `g_MissionConfig.stage_id` is the authoritative stage identity throughout all mission flows. `stagenum` (integer) is ONLY resolved from `stage_id` at the exact point of consumption (e.g., just before calling `mainChangeToStage()`). Never store a stagenum integer and pass it around — store the catalog ID. Never call `mainChangeToStage()` with a hardcoded or locally-computed stagenum — always resolve from `stage_id` via `catalogResolveStage()`. This pattern applies to: mission select, match start, stage transitions, lobby, solo, MP, endscreen restart — EVERY flow. Added 2026-04-06 (S165 — B-119 stagenum=0x00 crash fix). Pattern: `catalog_stage_result_t r; catalogResolveStage(g_MissionConfig.stage_id, &r); mainChangeToStage(r.stagenum);`
- **Catalog registers ALL assets (unlock is a separate layer)**: The catalog must register every asset that exists, including SP-only heads and bodies. Whether an asset is available to a player in MP is a gameplay/unlock decision — it is NOT a catalog registration decision. The head registration loop in `assetcatalog_base.c` must iterate ALL entries in `g_HeadsAndBodies[]`, not just MP-reachable ones. The MP character selection UI checks unlock status to filter what is shown; the catalog does not filter. SP-only characters unlock for MP when: the player has beaten the mission where that character appears, OR the Unlock All cheat is active. Added 2026-04-02.
- **ImGui is the sole menu system**: ImGui menus (`pdgui_menu_*.cpp`) are the ONLY menu system. **P10 D5.7 COMPLETE (S184, 2026-04-08)**: all legacy PD native rendering removed from `menuRenderDialog()`, hotswap always routes to ImGui, F8 toggle disabled. The legacy `menuPush`/`menuPop` dialog stack is retained as plumbing (ImGui menus push dialog defs, hotswap intercepts renders), but zero native rendering paths remain. `menugfx.c` retained only for non-menu GBI utility callers (`hudmsg.c`, `credits.c`, `sched.c`). ALL menu work — bug fixes, state management, Esc handling, duplicate prevention, theme/tint, mouse capture — must target the ImGui layer. Menu stack architecture: push/pop with duplicate rejection, input context per menu. Theme = persistent visual identity (user-chosen, draws first). Tint = transient overlay (composites on top of theme, cleared on pop). Added 2026-04-02, updated 2026-04-08 (P10 D5.7 complete).
- **Mouse capture is driven by input context stack**: Each input context declares its SDL mouse mode (gameplay=relative/captured, menus=absolute/visible). `inputCtxSyncMouseMode()` runs at frame end to enforce this. `on_push`/`on_pop` callbacks handle transitions. **No menu may call `SDL_SetRelativeMouseMode` or `SDL_ShowCursor` directly** — the context system owns these. The deferred flush in `pdgui_backend.cpp` respects `pdguiIsActive()` (full context stack check). Added 2026-04-02, updated 2026-04-07 (S170: systemic enforcement via `inputCtxSyncMouseMode`).
- **No raw IP in any UI surface**: Players join via 4-word sentence connect codes only. No UI element may display or accept a raw IP address. Connect codes are the sole mechanism for sharing/entering server addresses. The IP is resolved internally and never shown. `g_NetLastJoinAddr` and `g_NetRecentServers` store raw IPs internally — must never be exposed in UI. Future server history must encode stored IPs back to connect codes for display. Added Session 49.
- **Connect code byte order**: `connectCodeEncode()/connectCodeDecode()` use host byte order (little-endian on Windows), NOT network byte order despite the header comment. Both sides use the same convention so round-trips are consistent. Do not apply `htonl()` before passing to these functions. Added Session 49.
- **Server is not a player**: Dedicated server sets `g_NetLocalClient = NULL` and `g_NetNumClients = 0` at startup. Slot 0 is free for real players. All code paths that dereference `g_NetLocalClient` must have a NULL guard. Do not assume the server occupies any player slot. Added Session 50 (B-28 fix).
- **ROM/mod check skipped on dedicated server**: The ROM hash verification and mod check in `CLC_AUTH` is gated behind `!g_NetDedicated`. Dedicated servers have no valid ROM — the check must not run. Use `!g_NetDedicated` guards, not stub workarounds. Added Session 50 (B-27 fix).
- **Identity profile is authoritative name source**: On PC, `identityGetActiveProfile()->name` is the canonical player name. The legacy N64 config field (`g_PlayerConfigsArray[0].base.name`) is only consulted as a fallback when the identity name is empty. New code reading player names must prefer identity profile. Added Session 50 (B-26 fix).
- **All builds are clean builds**: The "Clean Build" toggle was removed. Every build unconditionally deletes build directories before CMake configure. No incremental builds. This eliminates the class of CMake CACHE stale-value bugs (e.g., B-22 version baking failures). Added Session 50.
- **Rooms are demand-driven**: Rooms are created when players need them, not pre-allocated. Zero players = zero rooms. The permanent room 0 created by `roomsInit()` is a transitional artifact — R-2 removes it. Added Session 51.
- **No local multiplayer (single local player only)**: This port supports exactly one local human player (Player 0). There is no split-screen, no local co-op, and no local second player. All default binding setup (IMCs, `setupGameplayDefaults`) must target Player 0 only — no `for (p = 0; p < MAX_LOCAL_PLAYERS; p++)` loops in binding or IMC initialization. All 2P/splitscreen dialogs are dead code (confirmed S188). Any code path that initializes controls, bindings, or UI for players 1–3 locally is an error. Added 2026-04-10 (S188 decision; enforced S190 binding rework).
- **C-button actions vs Controller tab UI (PC)**: `ACTION_CBUTTON_*` remain valid InputActions for keyboard/mod bindings and legacy compatibility. Settings → Controls → **Controller** hides the **C-button group** in the bind table and visual mapper only (less clutter; aim uses sticks). Do **not** remove C-button actions from the actionmap or default IMC without an explicit product decision — this is presentation-only. Added 2026-04-20 (controller map + hold housekeeping).
- **Spawn raycast-budget near-hit threshold = `SPAWNPOOL_CAPSULE_RADIUS` (30.0f)**: `spawnPoolRaycastBudget()` in `src/game/spawnpool.c` rejects any candidate with a per-ray hit distance below 30 units. The value MUST equal the player capsule radius. Prior threshold (5.0f) allowed players to spawn inside railings/thin geometry that was within the capsule volume. Declared in `src/include/game/spawnpool.h`; do not shadow or localise. Budget-sum threshold (`SPAWNPOOL_BUDGET_THRESHOLD=1500`) remains the secondary filter. Added 2026-04-13 (S249, B-134 fix, commit `0b44b2b8`).
- **Room-settings mutations broadcast via end-of-frame dirty flag**: Leader-side mutations to shared room state (bot count, player count, scenario, arena, timelimit, scorelimit, weapon set, playlist add/remove) must set a file-static `s_RoomSettingsDirty`/`s_PlaylistDirty` flag and flush via `netSendRoomSettingsUpdate()` / `netSendRoomPlaylistUpdate()` at end-of-frame, gated on `g_NetMode == MPSETTINGS_NETMODE_CLIENT && lobbyIsLocalLeader()`. Do NOT broadcast inline during drag/scroll/slider interaction (packet storm). Server validates room-leader and rebroadcasts via `SVC_ROOM_SETTINGS 0x78` / `SVC_ROOM_PLAYLIST 0x79`. Reference implementation: `pdgui_menu_room.cpp::pdguiRoomScreenRender()` + `pdgui_menu_mpsettings.cpp::renderSelectTunes`. Added 2026-04-13 (S253, commits `5c4a689d`, `287b0bc4`).
- **`manifestClear` before `mainChangeToStage` during MP teardown**: Any callsite that changes stage while an MP match's `g_ClientManifest` still has entries MUST call `manifestClear(&g_ClientManifest)` first, or `mainChangeToStage()`'s `manifestMPTransition()` branch will diff the torn-down manifest against whatever is loading and access-violate. Known required sites: `pdgui_bridge.c:799` (`pdguiEndscreenExitToMainMenu`, F-0.4), `netmsg.c:1419` (`netmsgSvcStageEndRead`, L1-1), `net.c::netDisconnect` (Bug A, 2026-04-13). New callsites that change stage while holding an MP manifest MUST replicate the pattern. See [systemic-bugs.md](systemic-bugs.md) SP-13. Added 2026-04-13 (Bug A fix, commit `d37e9677`).
- **`mods/` tree depth is capped at two levels**: Discovery scanners (`modmgrScanDirectory`, `s_scanModChromeStyles`, `scan_mods_for_themes`) recurse **exactly one level** into any top-level entry that has no manifest (`mod.json`/`audio.ini`/`theme.json`) — supporting category folders like `mods/UI Chrome/<slug>/`, `mods/Weapons/<slug>/`, `mods/MP Maps/<slug>/`. Do not remove the depth cap; deeper recursion would walk arbitrary user-created trees and create surprising discovery behavior. When adding new mod-discovery scanners, replicate the same `register-or-recurse-once` pattern (see `modmgrTryRegisterModEntry` + `modmgrScanCategoryFolder` in `port/src/modmgr.c`). Nine-Slice Chrome tool saves to `mods/UI Chrome/<slug>/`. Added 2026-04-16 (S293).
- **`matchConfigMaxBotsForHumans(humanCount)` is the single-source-of-truth for bot cap**: All callers that compute the maximum bot count for a match MUST pass the actual human count — never hardcode `1`. The canonical helpers are `matchConfigCountHumans()` (counts SLOT_PLAYER in `g_MatchConfig`, min 1) when no external count is available, or the lobby-aware count (e.g. `scenario_save.c` passes the parsed `humanCount`, `pdgui_menu_room.cpp` uses the room's human count). SVC_ROOM_SETTINGS client rebuild must also use the same `matchConfigChooseBotTeam()` helper as the host for team assignment, to keep host/client slot views consistent. Added 2026-04-16 (S294 — B-144 fix).
- **Ready gate lifetime is bound to its room's lifetime**: When a room holding an active ready gate (`s_ReadyGate.room_id == room->id`, `s_ReadyGate.active == 1`) is destroyed, or when any client in `s_ReadyGate.expected_mask` leaves the room or disconnects, the gate must be aborted via `readyGateAbort()` so that `SVC_MATCH_CANCELLED` is broadcast and clients clear their countdown UI. The canonical hooks are in `roomLeave()` (`port/src/room.c`); `readyGateTickCountdown()` also carries a defensive "room missing" check. Added 2026-04-14 (Bug B fix).
- **Menu pool is the structural dedup layer for menu types**: `port/include/menupool.h` + `port/src/menupool.c` define a pre-allocated `s_Pool[MENU_TYPE_COUNT]` keyed by `menu_type_t`. `menuPushDialog()` consults the pool after the F-3.1 pointer-scan; denial is structural (returns without mutating g_Menus[]). The `nextsibling` auto-open loop consults `menupoolIsDialogActive(sibling)` and skips any sibling whose type is already active elsewhere. `menuCloseDialog()` releases every sibling's pool slot. Force-close sites (`pdgui_bridge.c` endscreen paths, `matchsetup.c` match start, `netmsg.c` stage handlers, `inputCtxShutdown()` nuclear reset) call `menupoolReleaseAll()` for bulk teardown. Several dialogdefs may map to the same type (PC + Pause main menu variants → `MENU_TYPE_MAIN_MENU`; arena/scenario/weapons/limits → `MENU_TYPE_MP_SETUP`). Unregistered dialogdefs pass through with no dedup (legacy-safe). The pool also supports optional input-context ownership via the `ctx` parameter of `menupoolAcquire` — reserved for future migration of the `s_*PushedCtx` pattern in ImGui renderers. See ADR `context/designs/input-authority-and-menu-pool-2026-04-13.md` §6. Added 2026-04-16 (S299 Phase 2).
- **Lifts must be registered in `g_Lifts[]` at stage-setup time**: `liftActivate(prop, liftnum)` registers a lift prop in the global `g_Lifts[10]` array keyed by `pad.liftnum`. Without the registration, `liftFindByPad()` returns NULL and stepping on a lift pad does nothing. The historical caller was only the AI-script command `aiActivateLift` (opcode `0x018d`, `src/game/chraicommands.c:8498`), which meant CI arenas (no AI scripts) had dead lifts. Fix lives in `src/game/setup.c::OBJTYPE_LIFT` -- auto-registers by reading `liftnum` from `PADFIELD_LIFT` on any of the lift's own pads. SP remains correct because the AI-script call writes the same pointer (idempotent). Any new MP map with a lift MUST have a valid `lift->pads[]` entry with a non-zero `liftnum` in pad data. Added 2026-04-17 (S310).
- **`romProviderHandle()` is internal to the catalog/provider layer** (Phase 4, S346, 2026-04-17): Game code (`src/game/`) must NEVER call `romProviderHandle()` or include `assetprovider_internal.h`. The allowed callers are `assetload.c`, `assetcatalog_api.c`, `assetcatalog_base.c`, `assetcatalog_base_extended.c`, `server_stubs.c`. For ROM file loads, game code uses `assetLoadRomToNew(filenum, method, loadtype)` (declared in `assetload.h`) or `fileLoadToNew(filenum, method, loadtype)` (declared in `game/file.h`). For stage file handles, game code reads from `catalog_stage_result_t` fields (`bg_handle`, `pads_handle`, `setup_handle`, `mpsetup_handle`, `tile_handle`). For body/head/prop handles, game code uses `catalogGetBodyHandle()`, `catalogGetHeadHandle()`, `catalogGetPropHandle()`. The SA-5a bridge functions (`catalogGetBodyFilenumByIndex` etc.) are `[DEPRECATED]` — only still present for callers of legacy APIs that require a raw filenum (e.g., `fileGetInflatedSize`, `modeldefLoad`).
- **Identity cookie is the reconnect authority (MASTER-C3, S393, 2026-04-19)**: `struct netpreservedplayer` records both `name` and a 16-byte `cookie[NET_AUTH_COOKIE_LEN]` server-issued at first `CLC_AUTH`. Reconnect to a preserved slot requires `netServerFindPreservedByCookie(name, cookie)` to match BOTH fields in constant time. Legacy name-only lookup (`netServerFindPreserved`) remains for advisory/diagnostic use but MUST NOT be used to gate a preserved-slot restore. Any future path that touches preserved-player state must use the cookie-gated accessor. Client-side cookie is module-static in `netmsg.c` and is cleared on `netDisconnect` — never persist cookies to disk.
- **Persistent bans live in `$S/bans.ini`, consulted in `netServerEvConnect` (MASTER-C2c/C2d, S393, 2026-04-19)**: `serverBansInit()` runs once at server start, after `hubInit()`. `netServerEvConnect` calls `serverBansIsBanned(ip)` before any client slot allocation — banned peers receive `DISCONNECT_BANNED` immediately. Adding a ban via `serverBansAdd` (or `netServerBanClient`) saves the file atomically. Bans are NOT replicated across servers — each operator's `$S/bans.ini` is independent.
- **Admin RCON token is hashed, never stored as plaintext (MASTER-C2a, S393, 2026-04-19)**: `serverAdminInit(cliToken, iniToken)` runs once at server start with tokens from `--admin-token` (CLI) or `[Admin] Token` (server.ini) — CLI wins. Tokens shorter than 16 characters are rejected (boot warning if accepted length is below recommended 32). `serverAdminVerifyToken` does constant-time compare against the stored SHA-256 (domain-salted `"pd2-server-admin-token-v1\n"`). Once `serverAdminInit` returns, all plaintext token memory on the caller's stack MUST be zeroed.
- **Room passwords are hashed at create time (SEC-14, S393, 2026-04-19)**: `roomCreateConfigured` accepts a plaintext password and immediately feeds it through `roomHashPassword` (domain-salted `"pd2-room-password-v1\n"` SHA-256) before storing. The plaintext is discarded. `roomCheckPassword(room, plaintext)` is the sole matcher — constant-time compare against `room->password_hash`. Open rooms have an all-zero hash and `roomCheckPassword` returns 1 for them unconditionally.

## Removed Constraints

These constraints have been explicitly abandoned. If a task involves working around one of these, **stop and propose the simpler approach**.

- **2026-03-01: N64 platform guards** — PC-only target. All 672 `PLATFORM_N64` guards stripped across 114+ files. Zero references remain. (Phase D1 complete)
- **2026-03-01: 4MB memory mode** — `IS4MB()` is compile-time `0`, `IS8MB()` is compile-time `1`. Compiler eliminates all 4MB branches. `g_Is4Mb` variable removed.
- **2026-03-01: N64 dead code** — All N64 assembly (.s), ultra/os, ultra/libc removed. Only ultra/audio, ultra/gu, and 4 ultra/io vi mode files remain.
- **2026-03-05: N64 micro-optimization** — Modern x86_64 HW. Prefer correctness over cycle-counting. Hand-rolled sorts, manual bit-packing, fixed-point math — replace with standard approaches.
- **2026-03-10: Host-based multiplayer** — Dedicated-server-only model adopted (Phase D9). Server runs headless or with ImGui GUI.
- **2026-03-12: N64 collision workarounds** — Legacy cdTestVolume/cdFindGroundInfoAtCyl hacks replaced by capsule sweep system (capsule.c). Use proper geometric solutions.
- **2026-03-15: 4-player bot limit** — Original N64 supported ~8 bots max. PC port supports up to 31 bots + 1 player = 32 total (participant pool). `MAX_BOTS=32` (S45, was 24), `chrslots u64` (S45, was u32). Pool sizes expanded (Session 17): NUMTYPE1=70, NUMTYPE2=50, NUMTYPE3=48, NUMSPARE=80, weapons=100, hats=20, ammo=40, debris=30, projectiles=200, embedments=160.
- **2026-03-18: N64 body/head restriction in MP** — `mpGetNumBodies` unrestricted. Full 63+ character roster available in network play.
- **2026-03-20: `--log` CLI flag requirement** — Logging is now unconditional (always on). Log filename depends on mode: pd-server.log, pd-host.log, pd-client.log.
- **2026-03-23: Shared memory pools for mods** — N64-era pre-allocated pools (modconfig.txt `alloc` values) replaced by dynamic `malloc`-based allocation. Each component manages its own memory. Advisory `hint_memory` field in `.ini` for UI display only.
- **2026-03-23: Monolithic mod structure** — Mods are no longer single directories loaded/unloaded as a unit. Replaced by component-based architecture where each asset (map, character, skin, etc.) is an independent folder with its own `.ini` manifest. See [component-mod-architecture.md](component-mod-architecture.md).
- **2026-03-23: Numeric asset lookups** — ROM addresses, table indices, and array offsets for asset identity are abandoned. All asset references go through the string-keyed Asset Catalog. This eliminates the root cause of B-13 (scale), B-17 (stage ID mismatch), and the entire class of index-shift bugs when mods change.
- **2026-03-24: g_ModNum integer mod selector** — `g_ModNum` (0=Normal, 1=GEX, 2=Kakariko, 3=DarkNoon, 4=GF64) fully removed. MOD_NORMAL/MOD_GEX/etc. constants removed. Asset Catalog is sole mod authority. (D3R-11, S45)
- **2026-03-24: modconfig.txt parsing** — `modConfigLoad()` and all parsing logic removed. Mods require `mod.json`. Dirs without `mod.json` are skipped by `modmgrScanDirectory`. (D3R-11, S45)
- **2026-03-24: Shadow asset arrays** — `g_ModBodies[]`, `g_ModHeads[]`, `g_ModArenas[]` static shadow arrays in modmgr.c removed. Catalog-backed caches (`s_CatalogBodies/Heads/Arenas`) are the only backing store. (D3R-11, S45)
- **2026-03-24: fileSlots 2D array** — `fileSlots[5][ROMDATA_MAX_FILES]` (per-mod file slot banks) flattened to `fileSlots[ROMDATA_MAX_FILES]`. Only slot 0 was ever active. (D3R-11, S45)
- **2026-04-02: net_hash wire format** — u32 CRC32 compact references (`net_hash`) are fully deprecated. All wire messages, save files, and APIs must use full catalog ID strings. The hash was an optimization that creates indirection away from actual asset identity and makes debugging harder. Do not introduce any new net_hash fields.
- **2026-04-02: Legacy N64 menu system** — `menuPush`/`menuPop` stack in `menumgr.c` is deprecated. ImGui menus (`pdgui_menu_*.cpp`) are the sole menu system. The legacy stack will be stripped entirely; do not add new entries to it or rely on its state.
- **2026-04-02: Integer-native match config** — `matchslot` struct no longer treats `mpbodynum`/`mpheadnum` as primary identity. Catalog ID strings (`body_id`/`head_id`) are primary. Integer indices are resolved from catalog only at legacy engine handoff. Do not pass raw integer indices through match config APIs.
- **2026-04-17: `chrslots` bitmask + `BOT_SLOT_OFFSET`** — B-12 Phase 3 removed the `u64 chrslots` field from `struct mpsetup` along with the `BOT_SLOT_OFFSET`, `CHRSLOTS_PLAYER_MASK`, and `CHRSLOTS_BOT_MASK` constants. The participant pool (`g_MpParticipants`) is the sole source of match slot state on both client and server. The legacy shims `mpParticipantsToLegacyChrslots` / `mpParticipantsFromLegacyChrslots` + `MpParticipant.legacy_slot` field are gone. If a task feels like it wants to read or write a chrslots bit, use `mpIsParticipantActive(i)` / `mpAddParticipantAt(...)` / `mpRemoveParticipant(...)` instead. Bot slots live at `MAX_PLAYERS..MAX_MPCHRS-1`.

## Index Domain Warning

Three separate index spaces exist and must not be confused:

| Domain | Array | Size | Valid Range |
|--------|-------|------|-------------|
| Stage table index (`g_StageIndex`) | `g_Stages[87]` | 87 | 0–86 |
| Solo stage index | `g_SoloStages[21]` / `besttimes[21][3]` | 21 | 0–20 |
| Stagenum | Logical ID (e.g., 0x5e) | N/A | Arbitrary |

Mod stages have stage table indices 61–86 but **no** solo stage index. Flowing a stage table index into `g_SoloStages[]` or `besttimes[]` is an OOB access. Phase 1 safety guards added (Session 23). Phase 2 will add `soloStageGetIndex()` lookup.
