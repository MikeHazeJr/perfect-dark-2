### Cheats consolidation

The 7 cheat dialogs (hub + 6 category sub-dialogs) collapse into a **single tabbed hub renderer** `renderCheatsHub`:
- 6 tabs: Fun / Gameplay / Jo Solo Weapons / Classic Weapons / Weapons / Buddies
- Each tab is a scrollable list of checkbox rows (radio behaviour for Buddies)
- Docked action bar: `Turn Off All` / `Unlock All...` / `Back`
- `Unlock All...` → opens inline Yes/No confirm modal (reuses `renderCheatsConfirmUnlock`)

Registration policy:
- `g_CheatsMenuDialog` → `renderCheatsHub` (no initial tab override, keeps last-used tab)
- `g_CheatsFunMenuDialog` → `renderCheatsSubRedirect` (pops self, sets `s_CheatsTab = TAB_FUN`). Safety net: if any legacy path still pushes the sub-dialog directly, we pop it back to the hub and switch the tab. Same pattern as Batch 3 `renderCiSettingsRedirect`.
- `g_CheatsGameplayMenuDialog` → redirect → TAB_GAMEPLAY
- `g_CheatsSoloWeaponsMenuDialog` → redirect → TAB_SOLO_WEAPONS
- `g_CheatsClassicWeaponsMenuDialog` → redirect → TAB_CLASSIC_WEAPONS
- `g_CheatsWeaponsMenuDialog` → redirect → TAB_WEAPONS
- `g_CheatsBuddiesMenuDialog` → redirect → TAB_BUDDIES
- `g_CheatsWarningMenuDialog` → `renderCheatsWarning` (dedicated, SUCCESS modal)
- `g_CheatsConfirmUnlockMenuDialog` → `renderCheatsConfirmUnlock` (dedicated, DANGER modal)

**Note on dialog handlers**: `cheatMenuHandleDialog` (cheats.c:405) is fired automatically by the menu runtime on OPEN/CLOSE for any of the 7 cheat dialogs whether hot-swapped or not. This means `func0f14a52c()` (HUD darken flag) and the piracy-check fingerprint both still fire. Preserved without duplicating.

### Cinema consolidation

`g_CinemaMenuDialog` → `renderCinemaList` (lives in `pdgui_menu_mainmenu.cpp` per plan).

Reuses the legacy `menuhandlerCinema` through the s194 call-through pattern:
- MENUOP_GETOPTIONCOUNT / MENUOP_GETOPTIONTEXT / MENUOP_GETOPTGROUPCOUNT / MENUOP_GETOPTGROUPTEXT / MENUOP_GETGROUPSTARTINDEX → populate the grouped list
- MENUOP_SET → delegate play-trigger to handler with `data->list.value` (handler itself sets `g_Vars.autocutgroupcur`/`left`, calls `menuPopDialog`/`menuStop`)

This way we **do not duplicate** the getNumCompletedMissions / g_CutsceneCountsByMission logic — we call the same handler the legacy menu list would.

### What is NOT covered (flagged)

Nothing load-bearing is dropped. Two items flagged for note:

1. **Marquee ticker animation**: the legacy menu shows an animated horizontal-scroll marquee for locked cheats with full localized strings (`L_MPWEAPONS_136..143`, `L_OPTIONS_251`). Our replacement uses a static hover tooltip with the same content. Visual animation is lost; informational content is preserved. Acceptable per Batch 3 precedent ("content absorbed, UX modernized").
2. **Tri-state `cheatIsUnlocked()` return value**: legacy `cheatIsUnlocked` returns 0/1/2 (2 = both unlocked via completion AND transfer pak). Our checkbox display is binary. The `2` case only affects display ordering in the legacy screen, not the actual enabled state. No behavioural loss.
