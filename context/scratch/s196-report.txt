Phase 2.1  TGA loader lift
  port/fast3d/pdgui_theme.cpp
  - s_decodeAndUpload (line 253): static s_Rgba32Buf[256*256*4] replaced with
    per-call malloc/free of rgba32 buffer sized to actual dims.  N64 decode
    path still honours its u8 width/height ceiling but the buffer no longer
    caps everything at 256 px.
  - s_loadTgaTexture (line 501): completely rewritten.  Now accepts both
    24-bit and 32-bit uncompressed TGA, parses image-id length, validates
    image type (rejects RLE and colour-mapped), and synthesizes alpha=0xFF
    for 24-bit sources.  Dynamic allocation sized for actual w*h.  No hard
    256x256 cap.
  - Extract path (line 1437) comment fixed — s_Rgba32Buf reference was stale.

Phase 2.2 + 2.3  Nineslice per-edge modes + src_inset / dst_corner_px split
  port/include/pdgui_nineslice.h
  - nineslice_def_t extended: legacy left/right/top/bottom + new src_left/
    src_right/src_top/src_bottom + dst_left/dst_right/dst_top/dst_bottom +
    top_mode/bottom_mode/left_mode/right_mode + has_split + has_per_edge_mode
    flags.  Legacy edge_mode and center_mode remain for backward compat.

  port/fast3d/pdgui_nineslice.cpp
  - s_parseNinesliceJson: teaches the parser the new schema fields
    (src_inset, dst_corner_px, top_mode, bottom_mode, left_mode, right_mode).
    Legacy flat left/right/top/bottom and edge_mode remain accepted.  New
    s_parseInsetObject helper parses the nested { top, bottom, left, right }
    sub-objects.  Back-fill logic runs after parse so any combination of
    fields yields a valid struct.
  - pdguiNinesliceRegister: now calls new s_backfillDef helper on the stored
    copy so programmatic callers (e.g. pdgui_theme_loader.cpp) that set only
    legacy fields still get a valid struct with derived src_*/dst_*/per-edge
    fields populated.  Log line updated to print both src_ and dst_ insets.
  - pdguiNinesliceDrawEx: rewritten to use def->src_* for UV calculation
    and def->dst_* for vertex positioning.  Per-edge modes (top_mode,
    bottom_mode, left_mode, right_mode) drive each edge strip independently
    with clamp-to-bounds handling for tiny draw rects.

  port/fast3d/pdgui_theme_loader.cpp
  - Zero-initialize nineslice_def_t stack struct before setting legacy
    fields + register call, so the new flag fields don't contain stack
    garbage.

Directory convention (S196):
  mods/base-game/         Template mods (write-protected from the save path).
                          Auto-extracted by the game at startup.  Users
                          should NOT edit these — all changes are
                          overwritten on next launch.
  mods/user/              User-editable clones.  Reserved for modmgrSaveAs
                          output (deferred follow-up).  Directory
                          convention in place, no auto-creation yet.
  mods/<anything else>/   Third-party mods loaded from any other path work
                          normally — no new restrictions on existing
                          locations.

Mod manifest schema extensions (S196):
  "template": true|false  (optional, default false)
    When true, modmgr flags this mod as is_template=1.  The save-over
    path (when implemented in a follow-up session) will refuse to write
    to this mod.
  "tags": [ "label", ... ] (optional, default empty)
    Free-form array of strings for UI grouping.  Common conventions:
    "base-game" — shipped with the engine
    "template"  — write-protected reference copy
    "chrome"    — provides UI chrome nineslice assets
    "theme"     — provides palette + textures
    Authors can invent their own labels.

modinfo_t fields (port/include/modmgr.h):
  s32  is_template;
  s32  num_tags;
  char tags[MODMGR_MAX_TAGS][MODMGR_TAG_LEN];    // MODMGR_MAX_TAGS=8
