--------------------------------------------------------------------------------
ROOT CAUSE (one-liner)
--------------------------------------------------------------------------------
port/src/crash.c references extern s32 g_ChrLastTickedIndex, but its
definition lives in src/game/chr.c which is NOT in the server's explicit
SRC_SERVER CMake list — so pd-server's link fails with "undefined reference
to g_ChrLastTickedIndex" while the client (pd) links fine via GLOB_RECURSE.

--------------------------------------------------------------------------------
OPTION CHOSEN
--------------------------------------------------------------------------------
Option C — guard the crash.c reference behind #if !defined(PD_SERVER) so the
server target simply does not reference the symbol. The server has no chra-
Tick loop, so the last-ticked-chr-index diagnostic is a client-only concern;
the log line degrades to "n/a (server build — no chr tick loop)".

Rejected alternatives:
  • Option A (add src/game/chr.c to SRC_SERVER): rejected — chr.c is 6676
    lines with deps on modelmgr, bondgun, chraction, bot, playermgr, etc.
    It would cascade into dozens of missing symbols. The server's minimal
    source list is explicitly decoupled from game rendering and must stay
    that way.
  • Option B (move definition to a shared TU like crash.c or a new
    crash_globals.c): rejected per Mike's direction. The server has no
    chr tick loop; forcing the symbol to exist on the server side would be
    dead weight. Server should degrade gracefully.

--------------------------------------------------------------------------------
MACRO CONVENTION
--------------------------------------------------------------------------------
Used the existing PD_SERVER macro (defined by the CMake target via
target_compile_definitions(pd-server PRIVATE PD_SERVER=1) at CMakeLists.txt
line 557). This is the established project convention — already used in
assetcatalog_api.c, navspawn.c, net.c, netmsg.c, updater.c, etc. No new
macro needed.
