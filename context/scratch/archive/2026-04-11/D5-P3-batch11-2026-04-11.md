### Note [A]: Character/player write path enhancement

The legacy `mpCharacterBodyListHandler` / `mpLoadPlayerMenuHandler` MENUOP_SET
paths write `g_PlayerConfigsArray[0]` **without calling `netClientSettingsChanged()`**.
This is a latent legacy behavior: on a **listen server** or **host**, the next
`netServerStageStart` / `netServerCoopStageStart` invocation picks up the new
body_id/head_id via its own `netClientReadConfig(g_NetLocalClient, 0)` call at
net.c:658 / net.c:772, so the SERVER sees the new character. But on a **remote
client**, the update lives in `g_PlayerConfigsArray[0]` only — the server never
learns until the client either:
 - (a) Connects again (`net.c:906` seeds `netClientReadConfig`), or
 - (b) Some other code path calls `netClientSettingsChanged()` (e.g., the modern
       netmenu.c Character dropdown at line 179 / 403 does this explicitly).

Both existing modern dropdowns in `netmenu.c` (lines 179, 403) CALL
`netClientSettingsChanged()` after `mpchrSetBodyByIndex`. The legacy `setup.c`
path does not. Mike's direction:

> "Ensure any network play properly passes menu info into the relevant match
>  start / end procedures. Enhance the room flow, don't disrupt it."

**Enhancement**: our ImGui renderer for `g_MpCharacterMenuDialog` and
`g_MpLoadPlayerMenuDialog` will call `netClientSettingsChanged()` after any
MENUOP_SET if `g_NetMode != NETMODE_NONE`. This brings the legacy setup.c path
up to parity with the netmenu.c path. Fully additive — legacy listen-server and
host flows see identical behavior; client flow gains eager propagation.

`netClientSettingsChanged()` is declared in `port/include/net/net.h` and is
idempotent (it re-reads `g_PlayerConfigsArray[0]` into local client settings
and schedules a CLC_SETTINGS send on next network frame — same path the
legacy in-lobby team dropdown at `menuhandlerNetTeamSwitch` has been using
since v17 and also what netmenu.c:403 does today).

## Username/password rows (legacy stats dialog tail)

The NTSC build includes a "USERNAME: / PASSWORD:" block near the bottom,
gated on `g_PlayerConfigsArray[g_MpPlayerNum].title != MPPLAYERTITLE_PERFECT`
(row is hidden unless the player has earned the Perfect title). This is
a legacy Easter egg (cheat unlock code). Ported behavior:
 - Render the rows only if `menuhandlerMpUsernamePassword(MENUOP_CHECKHIDDEN)`
   returns false.
 - Dynamic text from `mpMenuTextUsernamePassword(item)` reads `item->param`
   to pick username vs password — shadow menuitem with param set to
   0 or 1.

No network exposure. Local Easter egg display only.

## Load Settings UI redesign (dual-list vs. showpresets toggle)

The legacy design uses a single LIST whose contents switch between
"custom setups" and "presets" based on a `showpresets` flag toggled by
Menu-Alt (L2+R2 on gamepad, Tab on keyboard). The separate `g_MpLoadPresetMenuDialog`
exists because `g_MpQuickGoMenuDialog` pushes Load Preset directly with
`item->param = 1` so MENUOP_SET routes to QuickGo-on-load.

ImGui design:
 - `g_MpLoadSettingsMenuDialog` → single renderer that shows BOTH groups
   ("Presets" header + "Custom" header) in one scrollable list (legacy
   GETOPTGROUPTEXT/GETGROUPSTARTINDEX plumbing already groups them; we just
   render both headers unconditionally instead of toggling).
 - `g_MpLoadPresetMenuDialog` → separate renderer that shows only the
   "Presets" group and uses `mpLoadSettingsMenuHandler` with `item.param = 1`
   so MENUOP_SET routes through the QuickGo branch on click. This keeps
   the Quick Go flow intact.
 - Marquee row renders `mpMenuTextMpconfigMarquee(nullptr)` for the
   currently-focused row (legacy body reads `g_Menus[].mpsetup.slotindex`
   which the legacy LISTITEMFOCUS sets; we call LISTITEMFOCUS whenever
   the ImGui hover/select index changes).

## Load Player grouping

`mpLoadPlayerMenuHandler` exposes files grouped by device (`numdevices` groups,
`numfiles` total). Modern PC has only the implicit local device so grouping
is mostly cosmetic, but we preserve the legacy behavior: GETOPTGROUPCOUNT /
GETOPTGROUPTEXT render a sub-header per device, GETGROUPSTARTINDEX places
files under the right header.
