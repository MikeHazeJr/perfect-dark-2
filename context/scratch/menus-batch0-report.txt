NEW PRIMITIVE: pdgui_layout — DOCKED ACTION BAR + POPUP SCRIM
=============================================================================

pdgui_layout.h API:

  f32  pdguiActionBarHeight(void);
  f32  pdguiBodyHeightForActionBar(f32 avail);
  s32  pdguiBeginActionBar(const char *id);
  void pdguiEndActionBar(void);
  s32  pdguiActionBarButton(const char *label, s32 isFocused, f32 width);
  void pdguiPopupDarkenBehind(f32 alpha);

Design rule enforced: primary CTAs (Start / Accept / Confirm / Apply / Begin)
NEVER live inside the scrollable body. They always live in the docked action
bar, which is a fixed-height child at the bottom of the window. This
guarantees the user can see and reach the action at any scroll position, at
any resolution, on any aspect ratio.

Usage pattern adopted by Batch 0 fixes:

  float avail  = ImGui::GetContentRegionAvail().y;
  float bodyH  = pdguiBodyHeightForActionBar(avail);   // reserve bar space
  if (ImGui::BeginChild("##body", ImVec2(0, bodyH), false,
                         ImGuiWindowFlags_AlwaysVerticalScrollbar)) {
      // scrollable content
  }
  ImGui::EndChild();

  if (pdguiBeginActionBar("##actionbar")) {
      if (pdguiActionBarButton("Start Mission", isFocused, barW)) {
          // launch
      }
  }
  pdguiEndActionBar();

Audio cue: pdguiActionBarButton() plays PDGUI_SND_SELECT on activation (mouse
click OR gamepad A / keyboard Enter when focused). Every primary action fires
the same confirmation cue.

Popup scrim: pdguiPopupDarkenBehind(alpha) replaces ad-hoc
GetBackgroundDrawList()->AddRectFilled calls in endscreen.cpp, pausemenu.cpp,
solomission.cpp, training.cpp, agentcreate.cpp. Single primitive = single
place to tune the darken alpha across every modal popup. The call is
idempotent per frame (just a full-viewport rect on the background draw list).

GENERALIZED MODEL PREVIEW PIPELINE
=============================================================================

Before Batch 0:
  - pdgui_charpreview.c rendered head+body character pairs only.
  - pdgui_model_preview.cpp wrapped it with a character-only ImGui panel.
  - Batch 10 (training 3D screens) would need weapon / vehicle previews and
    had no pipeline to build against.

After Batch 0:
  - PdguiPreviewType enum: CHARACTER / WEAPON / VEHICLE / PROP.
  - pdguiCharPreviewRequestEx(type, id1, id2) resolves catalog entries and
    routes to the single-filenum or character path accordingly.
  - pdguiCharPreviewRequestFilenum(type, filenum) — low-level path for
    callers that already hold a resolved N64 file index.
  - pdguiCharPreviewRenderGBI hook now picks MENUMODELTYPE_HUDPIECE for
    weapon previews and MENUMODELTYPE_DEFAULT for everything else.
  - ModelPreviewKind enum in pdgui_model_preview.h mirrors the preview type
    for the high-level panel API.
  - pdguiModelPreviewDrawEx(kind, id1, id2, x, y, w, h, opts) is the single
    entry point for Batch 10 callers. pdguiModelPreviewDraw() is preserved
    as a CHARACTER shortcut — zero caller churn for agent select, agent
    create, room lobby, modding hub.
  - Tracking state unified — single (kind, id1, id2) tuple avoids redundant
    FBO re-renders on every frame.
  - Placeholder silhouette branches on kind (character stickman vs neutral
    box icon for weapons/vehicles/props).

Per-type camera tuning: Batch 0 ships the API shape only. The per-type
FBO size and camera distance table (plan item 2) is deferred to Batch 10
when the actual weapon/vehicle/prop models are wired up and can be visually
tuned. Current behavior: all types use the existing 256x256 FBO and the
default menu camera. This is called out as an intentional deferral below.

### Mission Select right panel — Start Mission docking

BEFORE:
  ##ms_right BeginChild (whole right panel)
    header (stage name)
    difficulty picker (3 rows)
    objectives list (BeginChild with hardcoded `objH = bodyH - 260.0f`)
    briefing text (BeginChild with hardcoded `briefH = avail - 60.0f`)
    Start Mission Button  <-- inside ms_right scroll region
    footer hint
  EndChild

  Problem: the "leave room for buttons" arithmetic was fragile. On low-res
  windows or ultra-wide aspect ratios where vertical space is tight, the
  Start button scrolled off the bottom.

AFTER:
  ##ms_right BeginChild (whole right panel)
    header (stage name)                  [FIXED, pinned]
    difficulty picker (3 rows)            [FIXED, pinned]
    footer hint                           [FIXED, pinned]
    ##ms_detail_body BeginChild           [SCROLL]
      objectives list
      briefing text
    EndChild
    pdguiBeginActionBar("##ms_action_bar")  [DOCKED, always visible]
      pdguiActionBarButton("Start Mission", startFocus, barW)
    pdguiEndActionBar()
  EndChild

  Result: Start Mission is always visible at the bottom of the right panel,
  regardless of resolution, scroll state, or briefing length. Objectives and
  briefing scroll independently inside the detail body. Difficulty picker
  and footer hint stay pinned so the user always sees the current context.

### Standalone Difficulty Dialog — "missing text" regression

ROOT CAUSE: the Agent / Special Agent / Perfect Agent rows used
ImGui::Selectable("##diff_row", ...) with an INVISIBLE label and then drew
the difficulty name via dl->AddText() as a post-hoc overlay on the draw list.
When langSafe(L_OPTIONS_251/252/253) returned "" (lang bank not resident at
dialog-open time), the AddText call had nothing to draw and the row appeared
blank. Same pattern bug on the PD Mode row and Cancel row.

FIX: replaced the invisible-Selectable + AddText-overlay pattern with real
ImGui::Selectable(rowLabel, ...) calls where rowLabel is constructed from
the localized string with a hardcoded English fallback:

  const char *locName = langSafe(k_DiffIds[i]);
  if (!locName || !locName[0]) locName = k_DiffFallbackNames[i];
  char rowLabel[128];
  snprintf(rowLabel, sizeof(rowLabel), "  %s    %s", locName, timeStr);
  ImGui::PushStyleColor(ImGuiCol_Text, textCol);
  ImGui::Selectable(rowLabel, isActive, ..., ImVec2(0, rowH));
  ImGui::PopStyleColor();

Same pattern applied to:
  - Agent / SA / PA rows (fallback: "Agent" / "Special Agent" / "Perfect Agent")
  - PD Mode row (fallback: "PD Mode")
  - Cancel row (fallback: "Cancel")

Now the text is a real ImGui widget rendered by the normal layout pipeline,
cannot be missed by z-order / clip-rect issues, and always shows SOMETHING
even if the lang bank is not loaded.

The colored badge dot on the left gutter is still drawn via dl->AddCircleFilled
as an overlay (it's a decoration, not a load-bearing identifier — the row
label carries the identity).

CHALLENGES REGRESSION FIX — ACCEPT CHALLENGE DOCKING
=============================================================================

pdgui_menu_challenges.cpp renderChallenges(): the Accept Challenge button
was inside the ##chal_detail BeginChild along with the challenge description.
If the description text grew long or the window shrank, the button scrolled
off-screen. Same class of bug as Mission Select.

FIX: split the right panel into an inner scrollable body
(##chal_detail_body) containing the header + completion summary +
description, and a pdguiBeginActionBar-hosted docked button at the bottom
containing the Accept Challenge CTA. The outer ##chal_detail BeginChild
still provides the visible panel frame. The window-level Back button
remained unchanged (it was already outside the scroll region).
