## Shadow-struct ABI

ABI-compatible with `struct menuitem` / `union handlerdata` in
`src/include/types.h:3342..3417`:

```c
struct s203_handlerdata_checkbox { u32 value; };
struct s203_handlerdata_dropdown { uintptr_t value; uintptr_t unk04; };
struct s203_handlerdata_list {
    union { uintptr_t value; intptr_t values32; };
    union { s32 unk04; u32 unk04u32; };
    /* tail padded by union below to max size */
};
struct s203_handlerdata_slider { u32 value; char *label; };

union s203_handlerdata {
    struct s203_handlerdata_checkbox checkbox;
    struct s203_handlerdata_dropdown dropdown;
    struct s203_handlerdata_list     list;
    struct s203_handlerdata_slider   slider;
    u8 _pad[256];
};

struct s203_menuitem {
    u8        type;
    u8        param;
    u32       flags;
    intptr_t  param2;
    intptr_t  param3;
    uintptr_t (*handler)(s32 op, struct s203_menuitem *, union s203_handlerdata *);
};
```

## Intentional simplifications

Two items are explicitly simplified from the legacy layout; both are flagged
per Mike's standing audit rule.

1. **Arena picker group-header rendering**: legacy list displays arena group
   headers with an inline "+/- group name" prefix mixed into the per-row
   text returned by `mpArenaMenuHandler` GETOPTIONTEXT.  Our ImGui replacement
   renders those exact strings as ImGui::Selectable rows without a separate
   tree widget, so the user sees the same "+/-" prefixes and clicking toggles
   collapse (legacy SET path handles the toggle).  Visual fidelity identical;
   we do not substitute a custom ImGui tree node widget.

2. **Scenario-option "More Options..." button** replaces the legacy native
   dialog-nextsibling tab-strip that draws g_ExtGameOptionsMenuDialog
   underneath each scenario-options dialog as a second page.  Our replacement
   renders it as a docked action-bar button that pushes g_ExtGameOptionsMenuDialog
   as its own modal.  Content parity is preserved (all 5 extended options are
   rendered by renderMpExtGameOptions); only the visual grouping is changed.
   This matches the Batch 2 precedent for Counter-Op/Co-op options where
   tabbed sub-pages were flattened to modal push.

Neither simplification drops a legacy function, option bit, or backing-store
write.  Both are UX-level surface changes.
