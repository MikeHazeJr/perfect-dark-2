# Modding

> Component-based mod system. Typed `.pd*` content files plus `.pdmod` transport archives. JSON manifest + INI components. VFS over archive handles. Asset catalog is the single registration target. Network distribution with SHA-256 integrity. Reserved-name discipline at two layers.

---

## What it is

A mod is made of typed content units (`.pdweapon`, `.pdprojectile`, `.pdentity`, `.pdcharacter`, `.pdhead`, `.pdbody`, `.pdarena`, `.pdmesh`, `.pdanim`, `.pdsfx`, `.pdvoice`, `.pdsong`, `.pdui`, `.pdfont`, `.pdlang`, etc.) and can be distributed as a `.pdmod` archive (zip with `mod.json` manifest) or a folder under `mods/`. Each asset inside the bundle (map, character, skin, audio, etc.) is an independent component with its own `.ini` manifest (or JSON content entry in `mod.json`) and gets registered as an `asset_entry_t` in the catalog. Mods are not loaded as monolithic units; individual components are. `.pdmod` is the package/transport envelope for sharing and online delivery; the typed `.pd*` files remain the content organization surface.

## `.pdmod` archive format

Standard zip central-directory layout. Contents:

- `mod.json` (required) - manifest with id, name, version, author, description, base_fallback, dependencies, content (bodies/heads/arenas arrays), template, tags, requires_restart.
- Component `.ini` files (maps, characters, skins, weapons, audio, hud) at known sub-paths.
- External-format assets are standard authored files such as `.gltf`, `.glb`, `.obj`, `.png`, `.tga`, `.wav`, `.mp3`, `.ogg`, `.ttf`, `.otf`, plus semantic `.json`, `.graph.json`, and `.ini` documents. Authored content packages and external-format `.pdmod` archives must not contain `.bin` or public TSV as final source; `.bin` is legacy-only, TSV is temporary forensic/migration debt, and private generated cache stays outside shipped archives. Typed `.pd*` packages are the preferred content-unit surface, while `.pdmod` is the sharing/online transport envelope.
- Runtime activation follows the public typed-archive source shape, not legacy selected-primary shortcuts. For example, `.pdarena` requires its Scenario archive member, `.pdscenario` requires the full scene/setup/navigation/graph bundle, and dependency archives cannot stand in for the authored source member of themes, materials, skins, HUDs, props, weapons, characters, projectiles, entities, or effects.
- Modding Hub Map Import is a source-layout staging tool, not a native map-dump converter. It may accept editable scene/geometry source (`scene.glb`, `scene.gltf`, `geometry.obj`) or typed `.pdarena` / `.pdscenario` content units and stage them under `mods/`, but native `.bg`, `.bin`, `.pad`, and `.setup` payloads are rejected before output. If a bare scene/geometry folder is imported, the generated descriptors must remain editable `scenario.ini` / `arena.ini` source and the staged output must preserve nested files recursively.

Path-traversal sanitization at parse time ([modarchive.c:13-17](../../port/src/modarchive.c:13)). One `FILE*` per archive for lazy per-entry extraction. Atomic write path: `modArchiveBegin / AddFileMem / AddFileDisk / Finish` streams to `.tmp` and renames on success.

## Manifest parsing

[modmgr.c:122-283](../../port/src/modmgr.c:122) hand-written token-by-token JSON parser sufficient for the `mod.json` schema. Same pattern as [savefile.c](../../port/src/savefile.c), [updater.c](../../port/src/updater.c). Falls back to filename-slug when `id` field missing. `audio.ini` fallback path for legacy audio mods.

`mod.json` content array supports embedded body / head / arena declarations alongside the file-based INI scan. Both paths converge on the same catalog registration API.

The parser reads only the **singular** `content` object (bodies/heads/arenas count arrays). The **plural** `contents` tag array (e.g. `["palette","menubg","shimmer",...]`) and the `assets` array are recognised FORWARD-LOOKING schema affordances with no runtime consumer yet -- they are intentionally `json_skip_value`'d at the unknown-key branch (documented inline in `modmgr.c`). `contents` is the documented source for the future mod-manager sub-type green-dot indicators; wire real consumers at that skip site when the UI lands. This is deliberate, not a parser bug (B-913). Public editable `mod.json` source stays the native client source; the skipped keys are author-facing metadata, not generated cache.

`mods-enabled.json` is optional clean-install state. The mod manager checks for the file before calling the generic file loader so missing no-mod state does not log as a file-load error; when the file exists, it remains the primary ordered enable list.

## Asset registration paths

Two paths, both ending in `assetCatalogRegister*`:

1. **INI scan path.** [port/src/assetcatalog_scanner.c:205-253](../../port/src/assetcatalog_scanner.c:205) walks component directories, parses `.ini` files, calls typed register functions (`assetCatalogRegisterBody`, `RegisterHead`, `RegisterArena`, `RegisterWeapon`, `RegisterAudio`, `RegisterHud`).
2. **JSON content path.** `modmgrRegisterModJsonContentBuf` parses `mod.json` content entries and calls the same `assetCatalogRegister*` functions.

Both paths use the typed catalog registration API; both flow into the same catalog rows. See [pillars/catalog.md](catalog.md) for the catalog model.

Network-distributed typed archives must populate the same catalog metadata and dependency graph as local archive scanning. Distribution parsing is not allowed to be a lossy preview pass: animation rows keep frame-envelope fields such as `bytes_per_frame`, `header_len`, `framelen`, and `flags`; texture rows keep `source_texnum` when a native `texture_id` is present; delivered model descriptors from `mesh.ini` / `model.ini` register as `ASSET_MODEL` with their public source file bound; delivered map and Scenario descriptors parse readable mode strings such as `mp|solo`; delivered weapon descriptors preserve existing-row fallback fields such as weapon id, runtime/mp indices, display name, dual-wield flag, and `requirefeature`; delivered `audio.ini` rows run through the shared audio parser so keymap, loop, envelope, category, and provider-source metadata survive; and delivered archives register generic `deps`, projectile `entity_ref`, and animation `target_body` reverse dependencies. If a new typed-archive field affects runtime loading, sharing, source-only proof, dependency closure, or generated-cache invalidation, update `netdistrib.c` beside `assetcatalog_scanner.c` and the relevant loader walker.

The catalog dependency graph is part of public source closure, not a preview-only hint. It must grow with active catalog dependency pairs so large custom packs or retained generated installs do not lose manifest expansion after the old 256-entry initial allocation; tests link the real dependency graph and prove dependency pairs beyond that boundary remain iterable.

Public `.pdweapon` source is split held-weapon graph source plus model/default metadata, not only a graph-runtime compile input. Weapon archives that declare model source, `primary_graph`, `secondary_graph`, `shared_context_file`, `settings_file`, `variables_file`, or preserved existing runtime defaults must keep those public source members visible after local scan, network delivery, base walking, catalog held-graph activation, and runtime adapter activation. `weapon.ini` and `_meta/manifest.json` must declare the same source members because base boot walking restores weapon source fields from the manifest. Base `.pdweapon` extraction currentness must require the manifest-visible `primary_graph`, `secondary_graph`, `settings_file`, `variables_file`, and `shared_context_file` fields before skipping, and must reject old `behavior_graph`, `shared_context`, `settings`, and `variables` descriptor names. `model_file` is required only when a held high-model mesh is actually embedded; model-less weapons must not advertise a fake `dependencies/assets/models/held_hi.pdmesh` source member, and model source cannot activate a weapon by itself. Runtime bindings expose the model source when present, graph/settings/variable members, private runtime slot, MP slot, weapon id, feature requirement, and dual-wield flag while catalog IDs remain the public asset identity. Catalog activation for loose/source-member weapons compiles held graph IR from the split `primary_graph` / `secondary_graph` / `shared_context_file` source bundle only; legacy single `behavior_graph` is not a valid release-format activation path. Fully custom user-created held weapons now get catalog-owned private runtime/MP slots in the current slot-indexed weapon runtime; that integer-only handoff is private migration debt and must not become a modder-authored field.

File-source SFX/voice playback must preserve native playback metadata before any ROM/static fallback. Public `.pdsfx` / `.pdvoice` archives carry editable `sample.wav` plus native `ALKeyMap` fields (`key_min`, `key_max`, `key_base`, `key_detune`, `velocity_min`, `velocity_max`), sample pan/volume, loop markers, and `ALEnvelope` fields (`attack_time_us`, `decay_time_us`, `release_time_us`, `attack_volume`, `decay_volume`). WAV-backed SFX/voice source must be PCM16 mono RIFF/WAVE for native playback parity, and descriptor/manifest `sample_rate_hz` plus `decoded_sample_count` must match the actual `sample.wav` header so catalog duration, loop scaling, and `SDL_LoadWAV` playback do not disagree. Standard imported audio sources that enter the shared WAV/MP3/OGG decoder must preserve decoded interleaved sample length; OGG decoders return samples per channel, so runtime conversion must multiply by channel count before playback. `sndStart()` resolves those FileProvider rows, combines native base pitch with gameplay pitch, applies sample pan/volume, passes native `fxmix`, `fxbus`, and the `ALKeyMap.keyMax` fxmix offset, and starts a live file-backed sound handle through `audioStartFileSound()` so public WAV sources can be stopped, repanned, repitched, looped, released, FX-event updated, and mixed through a bounded file-sound FX send/return path instead of being queued once and forgotten. Existing audio archives without `key_base`, `attack_time_us`, `velocity_max`, or matching WAV header metadata are stale and must regenerate. Residual audio parity to watch in playtests: exact N64 aux/reverb tuning and any subtle ALSound mixer behavior remain broader audit targets.

Public mesh and Scenario geometry source must honor the current integer-native runtime boundary. `.pdmesh` and `.pdscenario` sources may stay DCC-openable as GLTF/GLB/OBJ, but extraction must preserve original integer/fixed-point mesh semantics for coordinates, UV/tile units, room/portal membership, part/matrix bindings, and command order in source metadata, and user-created geometry import must explicitly quantize into documented native units with overflow/collapse checks. `.pdmesh` generated-modeldef builds now reject non-finite or out-of-range vertex/UV values before writing native `Vtx` arrays and warn when triangles collapse after native quantization; public `.pdmesh` conformance applies the same hard overflow checks to `model.obj`, `model.gltf`, and `model.glb`. Public `.pdcharacter` source is an assembler bundle, not just a selected body file. A character archive requires body source; head and portrait members are dependencies/metadata that cannot activate a character by themselves. A character archive that embeds body, head, or portrait members must declare `body_archive`, `head_archive`, and `portrait_file` as applicable in both `character.ini` and `_meta/manifest.json`; local scan, network delivery, metadata walking, `.pdmod` validation, and runtime bindings must preserve body, head, and portrait separately.

Public `.pdbody` and `.pdhead` source members are mesh archives, not archive-only decoration. Body/head activation requires `mesh_archive`; `hand_archive` is optional first-person dependency data and legacy `model_file` is not a valid body/head source fallback. Body archives that contain `mesh.pdmesh` or `hand.pdmesh` must declare `mesh_archive` and `hand_archive` in `body.ini` and `_meta/manifest.json`; head archives must declare `mesh_archive` in `head.ini` and manifest metadata. Local scan, network delivery, boot metadata walking, `.pdmod` validation, and runtime bindings preserve those members separately. Runtime body/head model activation must treat a `.pdmesh` source as a typed source archive and resolve its public `model.obj`, `model.gltf`, or `model.glb` member before readable-source modeldef compilation; it must not pass `.pdmesh` archive bytes to native modeldef loading. Body archive walking must also bind `hand.pdmesh` to the matching first-person hand `ASSET_MODEL` row, because bgun still queues that model through the private `handfilenum` runtime handoff before the renderer boundary is fully catalog-ID-native. Character body assembly must refuse unresolved body identity instead of substituting slot 0: if `catalogBodyIdByBodynum()` cannot resolve the requested body, rendering returns no model and logs the source-chain failure rather than displaying a different built-in mesh.

MP body/head selector positions are private runtime bridge indices, not public asset identity. The selector cache must cover the same catalog-backed private domain exposed by `modmgrGetBody()` / `modmgrGetHead()` and must map each selector row back to its catalog ID through `mp_index`; base-only 63-body / 76-head lookup tables are not sufficient once source-backed custom rows enter the selector list. Default-head selection, display-name overrides, bot setup, config restore, and random body/head selection should all recover catalog IDs through `catalogMpBodyId()` / `catalogMpHeadId()` instead of treating a missing base integer row as proof that source-backed geometry is absent.

Public `.pdmaterial` archives require authored `material.json` source. Texture and effect dependency archives are real material source members, not optional archive decoration, but they cannot stand in for the material source itself. A material archive that embeds texture or effect dependency archives must declare `material_file = material.json`, plus `texture_archive` and `effect_archive` as applicable, in both `material.ini` and `_meta/manifest.json`; scan/distribution primary selection and runtime activation require `material_file` / `material.json` while metadata walking and runtime bindings keep texture and effect dependency archives distinct so material import/render work can compile effects without hidden cache or ROM fallback.

Public `.pdtheme` dependency archives are real theme source members, not optional archive decoration. A theme archive that embeds UI, font, audio, music, or effect typed dependencies must declare `ui_archive`, `font_archive`, `audio_archive`, `music_archive`, and `effect_archive` as applicable in both `theme.ini` and `_meta/manifest.json`; local scan, network delivery, metadata walking, `.pdmod` path handling, and runtime bindings must keep those members distinct. Dependency archives cannot stand in for authored theme source: scan/distribution primary selection and runtime activation require `theme_file` / `theme.json` while retaining dependencies as separate binding members.

Public Scenario `scene.glb` source must carry editable texture coordinates, runtime room shading data, native material metadata, and material alpha behavior. Generated `.pdscenario` and nested `.pdarena` scenes use `TEXCOORD_0` for DCC authoring scale, `TEXCOORD_1` for runtime-repeat parity, `COLOR_0` for the room color/shade payload, and `alphaMode=MASK` / `alphaCutoff=0.01` for textures with non-opaque alpha consumed by the source renderer. Every material must carry `extras.pd2_material` with a texture command, primary/secondary image names, legal wrap modes, integer native material fields (`offset`, `shift_s`, `shift_t`, `min_lod`, `tile_flag`), and any secondary texture binding on runtime UV set 1. The source renderer must preserve both UV sets through CPU scene build, GPU upload, and shader sampling: PD-authored material extras keep primary sampling on runtime UV 1, standard/custom GLB materials may use their declared base texture coordinate, and secondary textures must honor their archived coordinate binding instead of flattening all layers onto one UV. Runtime source-scene drawing also requires a valid camera projection from the live player/VI camera path; if the VI FOV is temporarily unusable, the bridge may fall back through player FOV, zoom FOV, and the 60-degree default so a public `scene.glb` is not silently dropped. Stale Scenario GLBs without the current exporter stamp, `COLOR_0`, alpha-mask material metadata, or complete `pd2_material` extras must fail conformance and regenerate instead of rendering as flat texture-only, opaque-dark transparent geometry, or float-only preview geometry detached from native material semantics.

Scenario source-renderer proof should use the renderer-owned CPU probe before any live smoke retry. `scenarioSceneRendererProbeSource()` exercises the same `scene.glb` CPU build path as live activation and reports scene/material/texture counts without activating global renderer state or uploading GPU data. A probe failure is extraction/source-scene data failure; a successful probe followed by live visual failure narrows the fault to camera delivery, GPU upload, shader/render state, or draw integration. Shader compile/link failures are now explicit renderer failures: the source renderer logs `SCENARIO.RENDER: shader compile failed` or `SCENARIO.RENDER: shader link failed` with the GL info log and refuses source-scene GPU upload for that scene.

Public Scenario table source must be semantic JSON, not TSV. Scenario objectives, spawns, volumes, pads, navigation paths, waypoint/waygroup/cover tables, portals, objects, setup fields, and AI lists now load through JSON members such as `pads.json`, `setup.fields.json`, and `ai/ailists.json`; stale public Scenario TSV members are rejected by conformance/native-source guards and should be treated as extraction debt, not modder-facing source. Extractors should not build TSV diagnostic ledgers as a normal intermediate for public archives; if a TSV string remains, it should be stale-archive detection, migration forensics, or a deliberate bad-archive test.

Public archive metadata must follow the same no-TSV rule as archive members. `_meta/manifest.json`, descriptors, examples, and mod-tool templates must not point at stale `.tsv` names after the public source moved to semantic JSON, because those references are still part of the game-facing/modder-facing contract even when no TSV member exists.

Mod packaging and authoring UI enumeration must include every user-manageable typed archive family. Export-by-catalog-ID, `.pdmod` hot registration, Mod Manager component editing, and Modding Hub INI editing use explicit type lists, so those lists must stay aligned with the public archive families rather than only the older weapon/texture/audio set. Arenas, bodies, heads, meshes/models, animations, and tools are first-class for the relevant surfaces; model descriptors must accept canonical `mesh.ini` and compatibility `model.ini`.

Metadata-family archive walking must preserve distinct dependency/source members instead of binding every field to one selected primary member. In particular, `.pdcharacter` body and head archive members remain separate (`body.pdbody`, `head.pdhead`) while the primary source path may still be the selected body member used for activation. The same rule applies to prop model/behavior, effect graph/timeline, vehicle model/physics/behavior, mission scenario/objectives/briefing/graph, HUD texture/layout, material material/texture/effect, and theme theme/UI/font members, because runtime adapters consume those ext fields independently after boot-time public-source registration.

Public `.pdeffect` activation requires authored effect source. `effect_file` / `behavior_graph` and `timeline_file` are source members; `shader_id` is metadata only and must not make a runtime binding active by itself. A shader-only effect row is an incomplete source-chain, and a bare outer/primary `.pdeffect` path cannot replace the required graph or timeline member. Both cases should regenerate or fail validation instead of pretending the effect can be edited or rebuilt.

Extracted `.pdmission` archives must declare every public mission source member in both `mission.ini` and `_meta/manifest.json`. `mission.graph.json`, `objectives.json`, `briefing.json`, and the embedded Scenario archive are all runtime-visible source members; writing the files without manifest keys is an asset-chain bug because boot-time metadata walking restores mission source members from the manifest. Mission activation requires the full graph + Scenario + objectives + briefing source bundle: Scenario/objective/briefing members and bare selected primary paths cannot stand in for a missing mission graph or incomplete mission archive. Public mission conformance validates descriptor/manifest/source agreement and treats `briefing.json` as semantic JSON with schema `pd2.mission.briefing.v1`, not a placeholder sidecar.

Public `.pdhud` archives must declare HUD layout and texture source members in both `hud.ini` and `_meta/manifest.json`. Boot-time metadata walking restores `layout_file` and `texture_file` from the manifest, so a HUD archive that only declares those members in the descriptor is not base-equivalent even if the files are present and zip-openable. `layout.json` is required and is the activating source selected by local scan, network delivery, and runtime adapter activation; texture source is a separate visual dependency and is optional only when the archive truly has no `texture.png` / `texture.tga` member.

Runtime adapter bindings must preserve the same distinct members after catalog activation. Adapter code may select one primary/authored file for activation, but it must not collapse secondary public-source members into "first present wins" fields: prop model and behavior graph, skin source and texture, HUD texture and layout, and mission scenario/objectives/briefing remain separately visible to runtime consumers. If a family has more source members than the compact binding can represent, add the needed binding surface or a family-specific source table instead of dropping fields.

Generic runtime bindings are an all-family source visibility surface and must scale with active catalog rows. The binding table may keep a small initial allocation for efficiency, but it must grow for retained generated installs and large custom packs; fixed caps such as the old 256-entry table can make valid public archives disappear from runtime consumers even when extraction, scanning, and distribution were correct.

Scenario runtime bindings are not allowed to reduce a Scenario to only scene/collision/graph. A source-backed `.pdscenario` remains a bundle of scene, collision, rooms, portals, pads, spawns, volumes, objects, setup fields, AI lists, objectives, navigation, and level graph members after catalog activation. Runtime adapter consumers should read the explicit Scenario binding fields or the catalog row, not infer that missing generic dependency slots mean missing source. `portals_file = portals.json` is a first-class Scenario source member and must survive the same extraction, local scan, network delivery, base walking, path qualification, and runtime activation paths as pads, volumes, and objects.

Public `.pdskin` swatches and typed material/texture dependencies are real source members, not archive-only decoration. `swatches.json`, `swatches_file`, `material_archive`, and `texture_archive` must survive extraction, local scan, network delivery, metadata walking, `.pdmod` packaging path handling, and runtime adapter activation alongside `skin_file` and `texture_file`; stale base skin archives without `swatches.json` should regenerate, and user-authored skins that embed typed material or texture dependencies must keep those dependency archives visible to runtime consumers.

## Active invariants

Per [constraints.md](../constraints.md):

- **Mesh extraction preserves unresolved native part metadata instead of dropping archives** (2026-06-07, B-798). `.pdmesh` extraction must write real model archives even when some native part-table rows do not resolve to registered node ids. Preserve those rows in `model.parts.json` as `node=-1` with `node_unresolved=true`, keep node/part JSON present for rootless-but-sane modeldefs, and treat zero-triangle exports as diagnostics rather than fatal archive failures. The 2026-06-07 boot proof writes all 733 mesh jobs with `failed=0`, including formerly skipped title/training models.
- **`mods/` tree depth cap of 2 levels** (S293). Discovery scanners recurse exactly one level into top-level entries with no manifest.
- **Reserved names at two layers**: scan walker + archive-path-trusted check.
- **Catalog registers ALL assets**; mod content extends the catalog through the same typed registration API as base content.
- **Source-gate coverage is per public family, not per shared runtime enum**: `.pdsfx`, `.pdvoice`, and `.pdsong` all resolve through `ASSET_AUDIO`, but the all-family source gate must keep representative archive loads for each public audio family. Base `.pdui` rows must preserve their public `data/<romid>/ui/<slug>.pdui::texture.tga` FileProvider source even when the theme loader or UI walker refreshes an already-live texture. Non-Scenario archive coverage also has an exhaustive generator at `tools/smoke-verify/run-all-family-source-matrix.ps1`; it enumerates every extracted public typed archive except `.pdscenario`, batches source-only debug catalog loads under the CLI argument limit, and keeps Scenario on the separate stage-load matrix because Scenario parity requires booting stage runtime products, not only loading catalog rows.
- **MP3-backed voice archives must play through the SFX/voice source path** (2026-06-08, B-865). Public `.pdvoice` archives may use either `sample.wav` or `sample.mp3`. Catalog voice/SFX overrides must keep `sample.mp3` in the file-backed SFX/voice state machine instead of treating it as music or accepting ROM fallback, so native-style pitch, sample pan/volume, key-volume, loop/envelope, and FX mix/bus behavior still apply. The current retained generated set has 104 MP3-backed `.pdvoice` archives.
- **Base UI `.pdui` clean-boot source is post-`texReset()`** (2026-06-07). The early boot emitter may return 0 before `g_TexGeneralConfigs` exists, but the normal runtime producer is now `texReset()` -> `bootEnsureUiArchivesReadyAfterTextureInit()`: emit `.pdui`, scan UI through the universal walker, dirty catalog caches, and reload theme textures from public `.pdui` source. `pdguiThemeCheckExtract()` remains a stale/missing-file repair path, not the first clean-install producer.
- **Source matrices can reuse one frozen extracted install** (2026-06-06, c3844 closeout). `tools/smoke-verify/run-scenario-source-matrix.ps1` and `tools/smoke-verify/run-all-family-source-matrix.ps1` accept `-Install` so runtime-only source checks can reuse one extracted `data/<romid>` set. Use this when extraction/schema did not change. The all-family matrix must keep writing `type=id` rows to its generated asset-list file and pass that file through `--debug-load-catalog-assets-file` instead of expanding thousands of asset IDs on the command line.
- **Modding asset references are catalog IDs, not numeric handles** (2026-05-22). Modding tools, typed archive descriptors, nested dependency inventories, generated live files, and picker/dropdown surfaces must use human-readable catalog IDs in `[namespace]:[asset_type]_[name]` form. Numeric file numbers, model slots, sound IDs, animation slots, body/head numbers, and similar legacy handles may not be used as catalog IDs or modder-facing asset references.
- **Public typed archive references reject legacy numbers** (2026-05-25, c3842). The asset native-source guard fails public typed archive text that uses numeric or legacy-symbol asset-reference fields such as `model_id`, `modelnum`, `filenum`, `weapon_id`, `sound_id`, `texnum`, `MODEL_*`, or `FILE_*`. Scenario extraction no longer writes raw `setup.tsv`, `mpsetup.tsv`, or `visual_segments.tsv` public dumps because those exposed legacy model/table numbers instead of catalog IDs.
- **Public typed archive references must resolve to actual catalog names** (2026-05-27, c3844; updated 2026-06-06). Strict conformance collects catalog IDs declared by root and nested typed archives, then rejects unknown catalog-looking refs in descriptors, JSON graphs, semantic structured source files, and `_meta/manifest.json` dependency records. A syntactically valid `base:*` string is not sufficient; generated and authored references must name an actual catalog entry or an embedded dependency in the closure. Any remaining public TSV/CSV asset-reference columns are migration debt, not the final authoring contract.
- **Scenario model references require `.pdmesh` archive closure** (2026-05-28, B-387). Scenario `objects.json` model catalog IDs are user-facing asset references and must point at real on-disk catalog archives. Base `.pdmesh` extraction now emits every `NUM_MODELS` `g_ModelStates` catalog model through `catalogModelIdByModelnum()`, so strict conformance can prove scenario model refs are editable/archive-backed instead of silently depending on private model slots.
- **`.pdmesh` skeleton metadata and nested source lookup are source-safe** (2026-05-28, B-388). Generated modeldefs may still carry legacy small skeleton tokens such as `SKEL_HEAD`; public-source export treats those as IDs instead of dereferenceable pointers, preserves `SKEL_HEAD` metadata, and resolves nested `.pdhead::mesh.pdmesh` manifests from the innermost archive path. This keeps all-model mesh extraction and source-gated weapon matches from stalling before runtime archive loading.
- **`.pdmesh` public source carries semantic hierarchy/render parity data** (2026-06-06, B-769; updated B-772/B-777/B-803/B-863). The extractor writes public OBJ `vt` rows as `Vtx.s/t` divided by 32 with inverted `t`, emits `usemtl` switches for texture-marker boundaries, and writes public MTL metadata using catalog texture IDs plus renderer mode fields. Public `.pdmesh` archives include `model.nodes.json`, `model.parts.json`, `model.faces.json`, and `model.render.json`, named source files that preserve hierarchy, part lookup, face matrix bindings, per-render-node material switches, original modelview matrix commands, `G_POPMTX`, matrix flags, and triangle draw order; stale mesh TSV sidecars are forbidden. `model.parts.json` may preserve duplicate native part numbers and unresolved native rows with `node_unresolved = true`; generated runtime part-table rebuilds skip explicitly unresolved rows instead of rejecting the whole hierarchy. Current model/scenario runtime payloads still depend on integer/fixed-point vertex, UV/tile, room/portal, part, matrix, and render-order data. Extracted base `.pdmesh` and `.pdscenario` sources must preserve those native integer semantics in editable metadata, and custom GLTF/GLB/OBJ imports must document and apply a reproducible quantization step before generated runtime modeldefs/scene caches are used. The Asset Pipeline migration, weapon graph parity lane, c3842 native-source correction, definitive optional-slot hardening, and c3843 remaining-family base-output pass are closed. - **`.pdmod` transport rejects loose public TSV payloads (2026-06-11, c3844-s110).** Folder packing, in-memory `.pdmod` writing, and direct archive registration now reject public `.tsv` payloads at the same boundary as authored `.bin` payloads.
