# Authored sample regression cases through Agent Select

Run each case on an admitted private copy of both the candidate dev and stable installs. Record channel, executable SHA-256, exact approved install package IDs/paths/hashes, starting save and cache state, startup log, and captures from the ordinary picker and map list. Use separate private saves per case. The two-map staging receipt and the pistol candidate hashes are package evidence only. The Maian Crystal Pistol needs release eligibility before it counts as part of the candidate inventory.

Use ordinary title startup and the normal Agent Select and Mod Manager screens. Use the production create and accept actions. The existing `tools/smoke-verify/tests/menu_virtual_controller_agent_create.json` is a reference for actual controller create, save, and load witnesses. For the full cases, use ordinary picker and map navigation and retain observed captures. Direct match launch, forced mod activation, pre-enabling fixture mods, and `--launch-load-agent` invalidate the clean UI proof.

| Case | Starting state and procedure | Required result |
| --- | --- | --- |
| `agent_clean_default` | Fresh install with its normal bundled packages. Private profile has no Agents, no `mods-enabled.json`, and no saved legacy mod selection. Start, create a new Agent, select it, and wait until its main menu becomes active. | Startup selects only approved bundled IDs in inventory order. Agent creation and activation retain that selection. `agent_*.json` captures the ordered IDs. Blank Room and Model Room are visible under Templates. Once the pistol is eligible, the weapon picker shows Crystal Pistol with `mod_crystal_pistol:crystal_pistol`. An unrelated ordinary user mod installed in a separate control copy stays disabled. |

Exit cleanly, restart the same copy, and select the saved Agent through Agent Select. | The same approved IDs and picker/map visibility survive restart and the real Agent transaction. The package is still available after `AGENT.SESSION: activation committed`; a startup mount by itself cannot pass. |
| `agent_disable_and_restart` | From an active Agent on a clean copy, disable Blank Room using Mod Manager and apply/save. Leave Model Room enabled as a positive control. Capture both the `mods-enabled.json` selection and that Agent's `enabled_mods`. Exit, restart the same install and private save, then select the same Agent. | Blank Room is discoverable on disk but disabled before and after selecting the Agent. It has no enabled catalog/picker row and stays absent from Templates. Model Room remains available. Both saved selections omit Blank Room. Record any mount, unmount, or transient catalog change across Agent activation. |
| `agent_saved_empty_is_explicit` | Match the clean case's package, cache, and empty Agent state. Seed the private machine `mods-enabled.json` with a valid `[]`, keep legacy settings identical, then create and select a new Agent. Restart and reselect it. | The loader recognizes the saved empty selection. No bundled gameplay sample activates before or after Agent selection. The Agent document saves `enabled_mods: []`, and both pickers remain empty of the samples after restart. Compare with `agent_clean_default`, where the file is absent and samples are visible. |
| `agent_existing_choices_and_user_mods` | Stage a validated existing Agent with explicit `enabled_mods` and two installable ordinary user test mods with distinct IDs. Pin a non-default order for the explicitly selected pair, leave one additional ordinary user package disabled, and use the supported same-ID precedence control on a separate copy. Include a case where the existing Agent's selection is `[]` against globally enabled samples. | Agent activation honors that Agent's exact choices, including `[]`. Automatic defaults do not enable arbitrary gameplay mods or transfer to an unreviewed same-ID user copy. Saved order and profile-copy precedence remain observable in the appropriate existing-config control. Record the B-1083-style before/after catalog transition independently of the clean new-Agent result. |

For each case record package discovery, selection source, the per-Agent profile before and after activation, the `AGENT.SESSION` commit, and the catalog or UI witness after that commit. Preserve screenshots of the actual template and weapon lists. A pass requires the positive controls to be visible as well as the expected disabled items to be absent. The release's `audio.ini`-only behavior is a separate control. Such tracks remain browseable through their existing audio admission path even when an ordinary gameplay mod is disabled. Their visibility cannot satisfy a gameplay-package enablement assertion.

## Product boundaries

- `modmgrLoadConfig` already returns on a successfully loaded JSON file, including `[]`. The pending production change is to admit the exact shared, verified bundled inventory only at the absent-selection boundary. A malformed selection must continue to fail closed. Preserve explicit legacy selections and the existing user-copy rules.
- `prefsAgentInit` captures the boot-time baseline and new Agent creation captures live preferences. `prefsAgentCommitSnapshot` calls `prefsApplyMods`, which can rebuild the mounted catalog during activation. Preserve explicit existing Agent lists. A clean new Agent must carry the verified defaults in its own document. If an integrated candidate fails one of these cases, identify whether the baseline, snapshot save, or activation lost the intended selection before changing that owner boundary.
- Leave the independent audio-only path and unrelated package behavior in place. No product edits were made for these acceptance cases. All dev and stable runs are pending actual integrated candidates and admitted runtime.
