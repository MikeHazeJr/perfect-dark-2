=============================================================================
DESIGN LAYER STRATEGY
=============================================================================

The S192 primitives (`pdguiBeginActionBar`, `pdguiActionBarButton`,
`pdguiEndActionBar`, `pdguiPopupDarkenBehind`, `pdguiBodyHeightForActionBar`)
already covered every Batch 2 need.  No new primitive was required.

The four renderers were implemented as:

- `renderCoopAntiDifficultyImpl(isCoop, windowId)` — shared difficulty
  body.  Differs from the existing `renderDifficulty` by:
  - No PD Mode row (pdmode is solo-only).
  - Difficulty row confirm pushes CoopOptions / AntiOptions (not
    AcceptMission directly).
  - Co-op flavour checks `isStageDifficultyUnlocked`; anti flavour
    does not gate (matches legacy).
- `renderCoopMissionDifficulty` / `renderAntiMissionDifficulty` —
  thin wrappers that call the shared impl.

- `renderCoopAntiOptionsImpl(isCoop, windowId, fallbackTitle)` — shared
  options body.  Renders checkbox and dropdown rows in a scrollable
  body, docks Continue / Cancel in a `pdguiBeginActionBar` child.
  Fires `menuhandlerBuddyOptionsContinue(MENUOP_SET)` on Continue so
  the legacy handler chains to `g_AcceptMissionMenuDialog`.
- `renderCoopOptions` / `renderAntiOptions` — thin wrappers.

All state read/write delegates to legacy menu handlers in mainmenu.c
via forward declarations and shadow struct types (s194_menuitem,
s194_handlerdata).  The shadow types are byte-identical to the real
types in `src/include/types.h`; the C linker matches by symbol name
only, and the x64 calling convention makes the calls ABI-compatible.
Same pattern used by `pdgui_menu_warning.cpp` for slider handling.

S194 does NOT extend the S192 primitives.  All dialog renderers build
only on the existing primitive surface.  If a later batch needs a
dropdown primitive, checkbox primitive, or settings-row primitive,
they should be added cleanly at that point; we did not extract them
preemptively because Batch 2 has only 3 checkbox sites and 2 dropdown
sites (2 and 2 if you count the options dialogs), which is below the
"three similar lines" threshold for extraction.

ANTI-PATTERN PROTECTION -- SELECTABLE-WITH-LABEL PATTERN
=============================================================================

The root cause of the S192 missing-text regression and the S193
LITERAL_TEXT regression was the same pattern: use an empty-labeled
`##hidden` Selectable and overlay the visible text via
`dl->AddText(...)` on the window draw list.  When langSafe() returned
an empty string (lang bank not resident at dialog-open time) or the
pointer bits of a literal text pointer were misinterpreted as a lang
index, the overlay text disappeared or crashed.

Every row in every S194 renderer uses a real
`ImGui::Selectable(rowLabel, isActive, ..., ImVec2(0, rowH))` call
where `rowLabel` is a `char[]` prepared with `snprintf` and a
hardcoded English fallback (e.g., "Radar On", "Friendly Fire",
"Perfect Buddy", "Main Player", "Continue", "Cancel").  Text is a
first-class ImGui widget, not an overlay.  The fix can never regress
this batch.

Audit grep:
  grep -n "##" port/fast3d/pdgui_menu_solomission.cpp | grep -i "selectable"
  -> no `##hidden` Selectable uses in any S194 code.
