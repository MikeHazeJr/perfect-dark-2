### Investigation

Read `Build/pd-client.log` (the latest run, 2026-05-13 13:46, version dev dbb57ef9). Key signals:

1. `pd.ini` has `SkipIntro=1` (line 104).
2. Boot flow at `port/src/main.c:505-507` honors `g_SkipIntro` by jumping straight to `STAGE_CITRAINING` (0x26) instead of the normal `STAGE_TITLE` flow.
3. `mainLoop` at `port/src/pdmain.c:485` detects `g_StageNum != STAGE_TITLE` and calls `titleSetNextStage(0x26)` -- bypassing the entire legal / intro title sequence.
4. Stage 0x26 (CITRAINING) loads. Its AI script starts the CI fly-in cutscene at frame 1 (`[00:12.48] ACTIONMAP: activated 'cutscene' (priority 4, depth 3)`).
5. `tickmode=6 (TICKMODE_CUTSCENE)` for the ENTIRE 67-second session. Never transitions. The cutscene plays but never reaches its end frame because the title-sequence machinery that would have advanced it is absent (skipped).
6. The file-select auto-open path at `src/game/menutick.c:351` is gated on `g_Vars.tickmode != TICKMODE_CUTSCENE`. With the cutscene stuck, the gate never opens. **Deadlock.**
7. First menu acquisition at `[00:17.53]` was a manual `agent_select` push by the user pressing a key, NOT the auto-open path.

Mike's "black screen, seems to do nothing" symptom matches the stuck-cutscene deadlock: the CI fly-in is running but the camera passes through interior geometry rendering as dark / black, and no UI is on top because the auto-open is gated.

### Fix

`src/game/menutick.c:348-371`. Added a watchdog to the file-select auto-open block. Old condition:

```c
if (g_Vars.lvframenum > 30 && g_Vars.tickmode != TICKMODE_CUTSCENE) {
```

New condition:

```c
const s32 cutscene_watchdog_ready =
    (g_Vars.tickmode != TICKMODE_CUTSCENE) || (g_Vars.lvframenum > 300);

if (g_Vars.lvframenum > 30 && cutscene_watchdog_ready) {
```

Effect: if the cutscene hasn't ended within 5 seconds (300 frames at 60 fps), force-open the file menu anyway. The cutscene continues running underneath as wallpaper.

Normal title-sequence flow ends the CI cutscene well within 5 seconds, so the watchdog only fires on the SkipIntro deadlock path. The fix is targeted and reversible (revert single conditional).

## Decisions

- **Watchdog over rip-the-gate-out**. Could have just deleted the `tickmode != CUTSCENE` gate entirely. Decided against because the gate exists for a reason (wait for the cutscene to be done so it acts as wallpaper) and removing it would change behavior on the normal-boot path. The watchdog preserves normal behavior + breaks the deadlock.
- **5-second timeout, not 1-second**. The normal CI fly-in is maybe 2-3 seconds. 5s gives margin. Could be tuned shorter (3s) but the wider margin is safer against any future cutscene-length changes.
- **Did not investigate WHY the cutscene appears black**. The visible blackness is a separate symptom -- the CI fly-in camera passes through interior geometry, OR the cutscene state is otherwise broken. Investigating that requires runtime debugging I cannot do from this environment. The watchdog masks the symptom by getting the menu visible. If Mike wants the cutscene to actually render the CI environment as wallpaper, that's a separate ticket.
- **Did not modify port/src/main.c's SkipIntro path**. Could have made SkipIntro=1 also force `tickmode = TICKMODE_NORMAL` at stage entry, bypassing the cutscene start entirely. Decided against because the AI script in CITRAINING starts the cutscene independently of g_SkipIntro -- the AI script doesn't know about that flag. Modifying the AI script's behavior at the C level is more invasive than the watchdog.
