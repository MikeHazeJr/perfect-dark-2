## Decisions

- **Worktree-disabled -> main checkout**. EnterWorktree returned the project's WorktreeCreate hook output: "Worktree creation is disabled for this project. Work directly in the main copy." Both commits go straight to dev.
- **c027 = kanban close-out only, no code**. Investigation showed the card was effectively done; title was a misread. Marked pending_completion with comprehensive evidence-refs (8 of them) so the orchestrator can verify and flip.
- **c036 = ship what's structurally cohesive, defer what shares a deep-plumbing blocker**. Per rabbit-hole protocol, four subtasks (s036-02 F-key migration, s036-03 Alt+Enter, s036-04 inputKeyPressed retire, s036-08 menu graph) collectively share two blockers (actionmap modifier-chord support extension, multi-session menu graph throughput). Mike explicitly said don't editorialize on realism, but I should also surface when work goes deeper than expected.
- **s036-01 wired as DECLARATIVE metadata only**. `inputLayerPush` / `inputLayerPop` do not currently consume the `.imc` field; each layer's callbacks call `imcActivate` / `imcDeactivate` directly. Wiring `.imc = &g_ImcGameplay` / `&g_ImcMenu` adds metadata without changing lifecycle. Comments explain why these two layers should NOT use push/pop-driven activation: g_ImcGameplay is the actionmap-init baseline (always on, never deactivated); g_ImcMenu is owned by the input CONTEXT stack (inputctx.c push/pop of g_CtxImGuiMenu / g_CtxPauseMenu / g_CtxDebugOverlay). Adding push-driven lifecycle would double-fire and shadow gameplay gamepad bindings (per the commentary at port/src/actionmap.cpp:2947).
- **s036-06 removes Forge IMC deactivates from observer pop**. The audit at audits/infrastructure-pillars-status-2026-04-27.md:129 had flagged this as "likely safe (deactivate of inactive IMC is a no-op) but a defect". Investigation confirmed `imcDeactivate` is idempotent (no-op when already inactive), so the change is behaviorally invisible today. But the symmetric structure prevents a future regression where a forge-active-during-spectator path could lose Forge IMC state on observer pop. Test pin updated to lock the new structure.
- **s036-07 syncs test spec to runtime, then locks via grep**. Found genuine drift: spec said deadzone=0.15 / exp=1.7 / max=1200 px/sec; runtime had deadzone=0.18 / exp=2.0 / max=28 px/frame at 60Hz = 1680 px/sec. The runtime was the truth (Mike has played with current feel). Synced the test's local spec to runtime values; assertions referencing 1200 updated to 1680; in-deadzone boundary test updated from 0.149 to 0.179. New `[scroll][static][link]` test grep-asserts the runtime contains exact constants and the `t * t` curve and the `gameplayInputSuppressed()` gate. Future drift in either direction fails the test.

## Blockers

- **Actionmap has no modifier-chord support**. `addBind(imc, ACTION, vk)` takes a single u32 VK; there is no way to specify `KMOD_ALT`, `KMOD_SHIFT`, `KMOD_CTRL` as part of the binding. This blocks: s036-02 (Shift+F1, Shift+F2, F2-no-mod, F6, F7, F8, F9, F10, F12, RS-click) and s036-03 Alt+Enter. Unblocking requires extending the binding struct + addBind helper + dispatch matcher to support modifier flags. Estimate +1-2 sessions for the extension alone; +1-2 more for the 10 action additions + dispatch wiring.
- **pd-tests runtime fails from PowerShell launch**. STATUS_ENTRYPOINT_NOT_FOUND (`-1073741511`) when launched via PowerShell Start-Process. Bash launch works (exit 0). Cause: MSYS runtime DLLs are on bash's PATH (via build-env-prelude) but not PowerShell's default PATH. Not a test failure, but worth a tooling follow-up so the test runner works uniformly.
- **build-session.ps1 -Target all only built client + updater**, not the full 4-target set. Had to run server and tests as separate `-Target server` and `-Target tests` calls. Each reused the same session id `sprc036` per the procedures' "reuse the same session id only inside the same active session" rule. May be a script semantics quirk (the `-Target all` arg may pass through to build-headless with a different interpretation than expected) or recent change. Worth checking.
