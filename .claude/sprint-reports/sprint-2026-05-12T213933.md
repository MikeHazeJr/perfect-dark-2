## Decisions

- **Push through perceived scope creep when the infrastructure already exists**. The prior turn's "blocker" framing was wrong. Investigation revealed VK_CHORD_* synthetic VKs and chordVkForKeysym were already in production use (CTRL+TAB / CTRL+Z / CTRL+S etc.). Extending the same pattern for three more chords (Shift+F1, Shift+F2, Alt+Enter) is incremental, not new framework work. Lesson: validate "blocker" claims by reading the surface area before declaring deferral.
- **F9 dual-effect preserved through consumer extension**. The raw F9 handler in pdgui_backend.cpp had been firing BOTH g_NetDebugDraw flip (via actionPressed shadow) and pdguiMenuStackOverlayToggle (direct call). Removing the raw handler exposed the actionmap binding to fire. To preserve the dual-effect, the consumer in pdsched.c now calls both. One key (F9), one action (ACTION_DEBUG_TOGGLE), two effects.
- **PD_DEV_BUILD gates at consumer site, not binding site**. Action enums and default bindings are unconditional; only the call to the handler is gated. Consistent with the existing pattern at actionmap.cpp:2469 (ACTION_TESTSCEN_CYCLE_COUNT). Keeps the action surface stable across dev / release builds.
- **gfxFullscreenToggle as a public C wrapper rather than vtable call**. pdsched.c could have called `gfx_sdl.set_fullscreen(!gfx_sdl.get_fullscreen_state())` through the GfxWindowManagerAPI vtable, but a single-line wrapper isolates the toggle semantics in one place and avoids exposing the C-vs-C++ vtable struct to pure-C callers.
- **inputKeyPressed joy-path retired entirely**. Audit found zero production callers passing VK_JOY_* after the F-key migration. Returning 0 for joy VKs (instead of a defensive log warning) keeps the deprecation surface clean. If a future caller surfaces, it will see "key not pressed" rather than a silent SDL controller poll; the right fix is to add an actionmap binding + consumer, not to revive the polling path.
- **s036-08 menu graph stays backlog**. Investigation revealed the 174 port + 160 src grep count was misleading (e.g. pdgui_menu_warning.cpp's single hit was a comment, not a call). True per-file inventory requires audit. L.16-L.39 in the design doc shows 24 prior single-edge commits, so realistic per-session throughput is 2-4 edges. Multi-session lane; track as long-running.
