## Shipped

### c106 code fix: voice cache bitfield unpack

Commit `21a36987`. One file: `port/src/romextract_pdsfx.c::s_buildVoiceCache`.

Root cause: the russ table's `soundnum` field is a PACKED bitfield (per `union soundnumhack` in `src/include/types.h:3484`). The leaf SFX bank index is in the 11-bit `id` subfield. The original cache builder used the raw `s16 soundnum` as the cache index, which wraps to negative for soundnums >= 0x8000 (e.g. 0x977a for "Carrington: Hello Joanna"). The `sfx_idx >= 0` guard rejected all wrapped negatives, leaving the voice_cache all zero. Mike's playtest log showed `pdvoice skipped=1545` (every leaf SFX classified is_voice=0) for this reason.

Fix: unpack via the union and use `hack.id` as the cache index.

```c
union soundnumhack hack;
hack.packed = g_AudioRussMappings[i].soundnum;
s32 sfx_idx = (s32)hack.id;          /* 11-bit unsigned, 0..2047 */
if ((u32)sfx_idx < cache_n) {
    cache[sfx_idx] = 1;
}
```

Mike playtest should now show pdvoice written > 0 instead of skipped=1545.
